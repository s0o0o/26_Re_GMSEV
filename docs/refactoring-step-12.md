# 12단계: 로그인 → 커마 → 접속과 배경 블러

이슈: https://github.com/s0o0o/26_Re_GMSEV/issues/15

## 사용자 흐름

1. 로그인 화면에서 숫자 계정 ID, 닉네임을 입력한다.
2. Enter로 커스터마이징 화면으로 이동한다. 이때는 서버에 연결하지 않는다.
3. 털·눈·목도리를 고른다. 뒤 배경만 블러와 어둡게 처리가 적용된다.
4. 접속 버튼 또는 Enter로 서버 연결과 로그인 요청을 시작한다.
5. 서버 로그인 완료 응답을 받으면 게임 화면으로 들어간다.

커마 화면의 뒤로/Esc는 로그인 입력으로 돌아가며 입력값과 외형을 유지한다.
접속 중에는 중복 요청과 뒤로가기를 막고 Connecting 상태를 표시한다.
접속·전송 실패나 거절·시간 초과가 발생하면 오류 안내와 함께 커마에서
재시도할 수 있다. 기존 로그인에는 비밀번호 인증이 없으므로 1단계는
로그인 정보 입력이고 실제 서버 조회는 최종 접속 시 수행한다.

## 코드 변경

- login_flow.hpp: 입력/커마/접속 중/게임 상태와 허용되는 전환을 관리한다.
- background_blur.cpp: 가우시안 커널로 가로·세로 두 번 배경을 흐리게 한다.
- HamsterCustomizer::setBackdrop: 원본 배경을 한 번 블러 처리해 텍스처로 보관한다.
- drawCustomizationScreen: 흐린 배경 위에 선명한 외형 UI·이름·뒤로/접속 버튼을 그린다.
- beginLoginConnection: 외형 확정 후에만 소켓 연결과 로그인 패킷 준비를 한다.
- pumpLogin: 비동기 송신의 부분 전송을 이어 보내고 로그인 응답을 확인한다.

TCP 연결 시도에는 2초 제한을 두었다. 이 최초 연결 호출 동안에는 UI가
잠깐 멈출 수 있다. 연결 후 로그인 응답은 프레임마다 확인하며 10초 제한을 둔다.
로그인 재시도에서는 이전 수신 패킷 조각을 버려 새 연결과 섞이지 않게 한다.
게임 리소스 초기화도 최초 연결 성공 시 한 번만 수행한다.

이전 화면은 커마 UI와 로그인 입력이 함께 표시되고 프로그램 시작 즉시
소켓을 열었다. 이제 로그인 입력에는 원래 배경을, 커마에는 블러 배경을
사용하고 최종 확인 뒤에 접속한다. 입력 필드의 ID/NAME 라벨과 긴 입력의
표시 폭도 조정했다. 서버/DB/패킷 형식은 이번 변경에서 바꾸지 않았다.

## 검증 중 발견한 자원 수명 문제

실제 client.cpp를 포함한 오프라인 렌더링 테스트에서 시작 전/종료 시
액세스 위반을 확인했다. 외형 텍스처와 폰트를 전역 객체로 즉시 생성하던
부분을 함수 지역 정적 객체로 바꾸어 실행 중 생성되도록 했다. 수정 후
동일 검증 프로그램이 화면 생성부터 정상 종료까지 성공했다.
