# AI 활용 기록

갱신: 2026-11-16 · [이슈 #56](https://github.com/s0o0o/26_Re_GMSEV/issues/56)

## 목적과 읽는 방법

이 프로젝트에서 사람이 무엇을 요청했고, AI에게 어떤 일을 맡겼으며, 결과를 어떻게 확인했는지 나중에 설명하기 위한 기록이다. 게임 구조는 [architecture](architecture/README.md), 변경 계약은 [SDD](sdd.md), 다음 작업은 [작업 큐](work-backlog.md)에서 읽는다. 이 문서는 AI의 내부 사고 과정이 아니라 관찰 가능한 요청·행동·판단 근거·검증 결과를 기록한다.

## 역할과 작업 흐름

사용자가 목표와 권한을 정한다 → 주 에이전트가 범위를 나누고 구현·도구 실행을 진행한다 → 필요한 경우 서브에이전트가 지정된 부분을 조사하거나 검토한다 → 주 에이전트가 결과를 확인하여 반영하거나 보류한다 → 테스트·이슈·커밋으로 근거를 남긴다.

이 프로젝트에서 말하는 서브에이전트는 게임 속 NPC나 Lua AI가 아니라 개발을 돕는 AI다. 서브에이전트의 ‘완료’는 맡긴 조사/검토가 끝났다는 뜻이며, 제품 전체의 테스트 통과나 main 병합을 뜻하지 않는다. 모든 작업에 여러 에이전트를 쓰는 것은 아니며, 사용한 경우에만 실제 역할을 기록한다.

| 구분 | 책임 | 결과를 받아들이는 기준 |
| --- | --- | --- |
| 사용자 | 요구사항·우선순위·DB 등 추가 권한 결정 | 사용자 요청/승인에 근거 |
| 주 에이전트 | 조사·명세·구현·검증·통합과 결과 설명 | 실제 코드/실행 증거를 직접 확인 |
| 서브에이전트 | 범위가 정해진 조사나 독립 검토 | 제안일 뿐이며 자동 승인/병합 아님 |
| 도구 | Git, 빌드, 테스트, DB 등 실제 작업 실행 | 반환된 결과와 로그 확인; 도구 호출 자체가 성공 증거는 아님 |
| Skill | 특정 업무의 재사용 지침 | 적용한 지침과 실제 영향 기록; 에이전트 개체와 구분 |

## 확인 가능한 과거 활용 — 사후 정리

아래는 2026-11-16 대화·완료 목록과 저장소 증거를 바탕으로 사후 작성했다. 역할 표는 완료 목록의 이름과 대화에서 설명한 역할 요약이며, 원문 위임 지시를 대조한 기록은 아니다. 당시 원문 지시·개별 검토 전문을 모두 보존한 기록은 아니므로, 정확한 투입 시간·비용·모델·모든 지적 사항은 확정하지 않는다.

| 완료 목록의 이름 | 맡긴 역할 | 확인 가능한 범위와 한계 |
| --- | --- | --- |
| Architecture reader | 기존 코드 구조 조사 | 구조 이해를 돕는 조사 역할. 이 이름만으로 특정 코드 변경을 이 에이전트가 작성했다고 단정하지 않음 |
| Spec reader | 명세·작업 기준 조사 | 구현 범위와 완료 기준 확인을 돕는 역할. 개별 채택/기각 제안은 원문 미보존으로 미확인 |
| Field finish review | 필드 작업 마무리 검토 | 필드 청크 작업의 검토 기록. 관련 작업 결과는 #54와 해당 명세/커밋에서 확인 |
| Impeccable finish reviewer | 화면·UI 품질 검토 | UI 검토 역할. 완료 목록만으로 모든 화면/기능 통과를 주장하지 않음 |

사용자가 공유한 화면에는 활성 0·완료 4로 표시됐다. 이는 그 화면을 공유한 시점의 상태이며, 이후 상태를 보장하지 않는다. 전체 과거 AI 사용 내역을 복원했다고 주장하지 않는다.

### 사용자와 AI가 나눈 결정

사용자는 넓은 필드를 유지하며 거점/집을 분리하고, 반응형 화면·주민 행동·옷장·구조 문서·작업별 미리보기를 요청했다. 주 에이전트는 이를 순서 있는 작업으로 나누었다. 실제 DB 전용 테스트 범위 재사용과 별도 외형 테이블 추가는 사용자 승인에 근거하며, AI에게 무제한 DB 변경 권한을 준 것으로 해석하지 않는다. 접속 정보와 비밀번호는 기록하지 않는다.

## 앞으로 매 작업에 남길 항목

AI를 사용한 작업은 관련 이슈와 이 문서의 날짜별 기록에 짧게 남긴다. 큰 증거는 원래 명세/테스트 로그에 두고 링크한다. 역할 분담과 검증이 바뀌면 같은 작업에서 갱신한다. 이 규칙은 다음 실행자가 읽고 수행하는 절차이지 자동으로 기록을 생성하는 Hook 구현은 아니다.

```text
날짜 / 이슈 / 작업·병합 커밋:
사용자 목표와 승인 범위:
주 에이전트가 한 일:
서브에이전트: 사용 안 함 또는 이름·맡긴 범위·완료 여부
반환된 제안과 주 에이전트의 채택/보류·이유:
사용 도구·Skill과 실제 영향:
검증: 코드 확인 / 실행 통과 / 실패 / 미실행을 구분
근거: 명세·명령·로그·미리보기(실제 캡처/렌더러 출력/목업)
남은 위험과 다음 작업:
```

분실한 지시나 근거는 ‘미확인’으로 적고, 나중에 추측해 원문처럼 채우지 않는다. 실제 모델/비용/시간을 측정하지 않았다면 숫자를 만들지 않는다. 비밀정보·개인정보·비공개 내부 추론은 저장하지 않는다.

- 주 에이전트: Git/원격 main 확인, #56 발행, 진행 중 옷장 변경을 보존하기 위해 최신 main의 별도 worktree/feature 브랜치에서 문서 작성.
- 지침: doc-coauthoring의 독자 관점·사실/한계 분리와 문서 검토 절차 적용. 별도 제품 동작 변경/SDD 명세/게임 빌드는 필요하지 않은 문서 작업.
- 독자 검토: `ai_usage_doc_review`에 이 문서만 전달하여 역할/NPC 구분, 완료 의미, 과거 근거 한계, 기록 절차, 옷장·부하 상태의 5개 질문과 모순 검사를 맡겼다. 다섯 질문을 문서 내용대로 답했고 뚜렷한 모순은 발견하지 못했다. 역할 표의 근거 수준을 더 명시하라는 제안을 채택하여 원문 지시 대조가 아니라 이름·대화 요약임을 추가했다. 이 검토는 사실 전체를 외부 검증한 것이 아니라 독자 이해 검사다.
- 검증: UTF-8 엄격 디코딩·문서 내 로컬 링크 존재·`git diff --check` 통과. 게임 빌드/실행은 문서 전용 변경이라 미실행. 최종 원격 반영과 커밋은 이슈 #56에서 확인한다.
