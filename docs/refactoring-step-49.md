# 49단계 — 거점↔필드 귀환 요청과 버튼

2026-11-16, #53. [명세와 완료 기준](specs/hub-field-travel.md), [현재 구조](architecture/travel.md).

기존에는 금색 포털을 밟아야 지역을 이동했고 TELEPORT 패킷은 빈 처리였다. 이제 우상단 버튼 또는 R키로 공용 거점에 돌아오거나 필드로 나간다. 개인 집 기능은 아니다.

서버가 목적지를 정하고, 같은 요청의 재전송은 이동을 반복하지 않는다. 이전 시야의 명시적 퇴장·추격 세대·섹터를 정리한 뒤 새 위치/지도/시야를 보낸다. 클라는 판정 전 위치를 옮기지 않으며 채팅 중 조작·누른 R키의 연속 왕복·응답 대기 중 중복을 막는다. timeout/거절/연결 종료에는 안내를 표시한다. 게임 송신은 부분 송신을 보존하는 큐를 거친다. 프로토콜 v3이므로 서버와 모든 클라 도구를 함께 빌드해야 한다.

검증: 실제 TCP/IOCP 4 worker + DB 대역, native 코드/파서 TCP 요청·분할 응답 및 입력 이벤트, 전체41회귀와 서버/native/GUI Debug·Release 6빌드 통과. 기존 주민 회귀에서 발견한 본인 대상 LEAVE 누락을 수정한 뒤 전체를 재실행했다. 실제 DB 부하를 새로 실행하지 않았다. 종료 중 네트워크 오류 로그를 0이라고 보고하지 않는다.

build/tests/travel-*.png는 생산 렌더러 테스트 출력이며 실제 OS/DB 게임 캡처가 아니다. 8상태·3해상도를 검토했고 독립 UI 검토는 ship이다. 기존 픽셀 자산/글꼴/팔레트를 유지했다. 전체 HUD/실제 F11 입력 검증으로 확대하지 않는다.

다음은 넓은 필드의 청크·충돌 자료 기반과 화면 밖 처리다. #10/#41 잔여 관측은 별도 유지하며 이 작업으로 해결 처리하지 않는다.
