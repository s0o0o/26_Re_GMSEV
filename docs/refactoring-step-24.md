# 24단계: 몬스터·씨앗 재생성과 AI 세대 관리

관련 이슈: #26

## 기존 문제

씨앗과 몬스터는 획득·처치 후 서버를 재시작해야 돌아왔다. 특히 AI 이동은 타이머와 IOCP 작업 큐에 미리 예약되므로, 부활만 추가하면 사망 전에 예약한 이동이 부활한 몬스터에게 적용될 수 있었다.

## 변경 위치와 흐름

- `shared/respawn_policy.hpp`: 씨앗 20초, 몬스터 30초 및 세대 번호 검사 정책.
- `monster_lifecycle.hpp`, `monster_state.hpp`: 사망 시 세대 번호 증가 → AI 비활성화 → 재생성 시간 기록. 부활 시 원래 위치·HP 5 복원 → 세대 번호 다시 증가.
- `myserver.cpp`, `iocp_operation.hpp`: AI 예약과 IOCP 전달에 세대 번호를 함께 저장한다. 타이머에서 한 번, 실제 실행 직전에 다시 검사한다. AI 실행과 사망·부활은 같은 몬스터 잠금으로 보호한다.
- `world_map.cpp`: 씨앗 획득 시간을 기록하고 기한이 지나면 타일을 복구한다. 맵 변경은 기존 맵 잠금으로 보호한다.
- 서버는 약 1초 간격으로 재생성을 확인한다. 복구된 씨앗은 주변 플레이어에게 맵 정보로, 부활한 몬스터는 기존 입장 패킷으로 알린다. 새 네트워크 패킷이나 DB 스키마는 필요 없다.

즉, `처치 → 이전 AI 작업 무효화 → 30초 대기 → 원래 위치에서 부활 → 주변 사용자에게 다시 표시` 흐름이다. 실제 표시는 검사 주기와 서버 처리 지연만큼 늦어질 수 있다. 씨앗 위에 서 있기만 해서는 자동 획득되지 않으며 다시 이동해야 한다.

## 검증

- 회귀 프로그램 13개 통과. 새 테스트는 부활 직전/정각, HP·위치 초기화, 이전 세대 거부, 중복 사망·부활 방지, 씨앗 반복 획득·재생성을 확인한다.
- 서버 x64 Debug·Release 빌드와 DB·네트워크 없는 `--startup-check` 초기화 검증 통과. 기존 C4244·LIBCMT 경고는 남아 있다.
- 실제 DB 부하테스트와 다중 클라이언트의 화면상 재생성은 이번에 실행하지 않았다. 테스트는 시간을 주입하는 DB 없는 검증이며 실제 30초 대기 테스트와 구분한다.
