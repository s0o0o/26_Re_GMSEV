# 33단계: 지역 ID와 경계 검증 (2A)

이슈 [#35](https://github.com/s0o0o/26_Re_GMSEV/issues/35), [사전 명세·완료 기준](specs/world-region-boundaries.md), [전체 로드맵](specs/world-display-roadmap.md).

## 기존 구조와 이번 범위

클럽하우스와 들판을 전역 X,Y 공간에 옆으로 붙여 놓고 거리와 x>=32로 구분했다. 현재 두 맵 사이의 빈 간격이 커서 대부분의 시야 혼합을 우연히 막아주지만, 지역이라는 기준 자체가 없으므로 새 맵 추가/간격 변경에 안전한 구조는 아니었다.

이번 작업은 지역 분리의 첫 단계(2A)다. **DB와 패킷의 X,Y를 지역 ID+지역 내부 X,Y로 완전히 바꾼 작업은 아니다.** 기존 형식 위에 명시적인 지역 변환과 상호작용 경계를 만들었다. 서버·클라이언트·스트레스 빌드 호환성을 유지한 뒤 후속 2B에서 저장/전송/섹터 컨테이너를 전환한다.

## 위치를 어떻게 이해하면 되나

`shared/world_regions.hpp`에 `Id`, `Position`, `Descriptor`, `decode`, `encode`, `same`, `inRange`를 추가했다.

| 의미 | 지역 내부 위치 | 현재 호환용 전역 위치 |
| --- | --- | --- |
| 클럽하우스 | Clubhouse, (10,10) | (10,10) |
| 들판 | SunnyPeak, (10,10) | (42,10) |
| 두 맵 사이 빈 공간 | Invalid | (24~31,y) |

같은 숫자의 지역 내부 좌표라도 지역이 다르면 다른 장소다. 변환은 지역의 폭/높이로 검증하고 음수, 범위 밖, 모르는 ID는 거부한다. `Invalid`끼리도 같은 지역이 아니다. 유효 지역과 걸을 수 있는 칸은 별개다. 벽도 지역에는 속하지만 충돌 판정에서 막힌다.

`GameObjectState::location()`은 기존 `_x,_y`를 변환해 지역 위치를 얻는다. region 필드를 따로 저장하지 않으므로 좌표와 region이 엇갈리는 이중 상태를 만들지 않는다. 실제 상태의 단일 원본은 아직 기존 좌표다.

## 바뀐 처리 흐름

- **시야/주변 검색:** myserver.cpp의 플레이어 시야, NPC 감지, 섹터 후보에서 거리 검사 전에 같은 지역인지 확인한다. 물리 섹터 배열은 이번에는 유지한다.
- **전투:** 공격 가능한 지역인지 descriptor에서 판단하고 타깃도 같은 지역인지 검사한다. `publishCombat`은 audience가 잘못 섞여도 다른 지역으로 전투 패킷을 보내지 않는다. `sendAddPlayerPacket`도 지역 경계를 검사한다. 모든 저수준 패킷 writer에 임의의 지역 필터를 넣은 것은 아니다.
- **Lua:** 발신 NPC와 수신자가 같은 지역인지 확인하고, worker의 이동 알림도 지역이 다르면 Lua에 전달하지 않는다. 기존 접속 식별자/generation 검증은 유지한다.
- **포털:** world_layout은 지역 내부 포털 좌표를 공통 변환으로 기존 좌표에 적용한다. 이동 전에 `cancelRegionChases`가 해당 플레이어를 쫓던 NPC의 generation을 올리고 추격/이전 관찰을 해제한다. 기존 이동 처리에서 플레이어 observer의 LEAVE와 새 목록을 갱신한다. 돌아왔다고 이전 예약이 살아나지 않는다.
- **A*:** 목적지가 다른 지역이면 경로를 탐색하지 않는다.
- **클라이언트:** 배경/지역 이름 판정에 같은 공통 지역 정의를 사용한다. 새 맵 그림이나 버튼은 이번에 추가하지 않았다.

포털의 추격 해제는 현재 NPC 목록을 조회한다. 필드 확장 시 NPC 수가 많아질 경우 지역별/추격 대상별 인덱스가 필요하며 이번 테스트를 고동접 성능 검증으로 확대할 수 없다.

## 검증 결과와 한계

- 좌표 단위 검사: 두 지역의 모든 정의된 칸 encode/decode 왕복, 같은 local 좌표의 지역 차이, 음수/빈 영역/초과 범위/잘못된 ID, 기존 포털 왕복 통과.
- packet fixture: 같은 local 좌표라도 다른 지역이면 enter/전투 fan-out 차단, 같은 지역은 전달, 추격 generation 무효화, A* 다른 지역 거부/같은 지역 경로 통과.
- 실제 4-worker/TCP + DB 대역 fixture: 기존 필드 로그인, 같은 지역 시야/메시지 양성 대조, 범위 안 Invalid 좌표의 시야/후보 거부, 필드 포털→클럽하우스 이동, 이전 observer LEAVE, 추격 해제, stale AI 거부, 다른 지역 Lua 알림/메시지 차단, 실내 공격 SafeZone과 HP/씨앗 불변 확인.
- 전체 27개 회귀 프로그램 통과. 이전 loopback fixture는 플레이어가 기본 실내 (0,0)에 있으면서 부활한 필드 NPC의 ENTER를 기대하고 있었다. 새 지역 경계에 맞게 플레이어/NPC를 필드 좌표로 명시한 뒤 통과했다. 새 단위 테스트의 initializer_list include 누락도 수정 후 재실행했다.
- 서버·클라이언트·스트레스 도구 x64 Debug/Release, 실제 Lua/맵을 사용하는 DB 없는 startup-check 성공. 기존 C4244/MSB8028/LNK4098 경고는 남아 있다.
- 실제 DB 접속/스키마 변경/장시간 부하/일반 게임 클라이언트의 접속 플레이 육안 검사는 미실행이다. 현재 유효한 두 맵은 전역 좌표 간격이 시야보다 넓어, 가까운 다른 유효 지역의 겹친 좌표 테스트는 공통 모델/packet fixture에서 하고 생산 시야는 Invalid 경계로 방어 검증했다. 실제 겹친 좌표 저장은 2B 대상이다.

## 미리보기

`tests/run-region-preview.cmd`를 실행하면 `build/tests/world-regions-preview.png`를 만든다. 기존 생산 `ClubhouseRenderer`, 실제 맵/햄스터/폰트 리소스로 두 장면을 나란히 그렸으며 출력 이미지를 확인했다. **DB에 접속한 게임 캡처나 새로 확장된 필드 완성본이 아니라 렌더 테스트 출력**이다. 이미지의 지역 ID/지역 내부 좌표/기존 좌표 표시는 테스트 설명용이며 게임 HUD에 추가한 것이 아니다.

앞으로도 완료 시 미리보기와 그 출처를 함께 제공하도록 AGENTS.md에 사용자 요청을 기록했다.
