# 32단계: 창 크기 대응과 전체화면

이슈 [#34](https://github.com/s0o0o/26_Re_GMSEV/issues/34), [전체 로드맵·완료 기준·실행 결과](specs/world-display-roadmap.md).

## 왜 고쳤나

client.cpp는 18×16칸에 칸당 50픽셀, 즉 900×800 창을 만들었다. 창 크기가 바뀌었을 때 공통 View를 갱신하는 처리가 없어서 그리기와 클릭 좌표를 일관되게 유지할 기반이 부족했다. 화면 크기와 서버가 보내는 주변 맵 크기는 서로 다른 문제다.

## 무엇을 바꿨나

- `display_layout.hpp`: 물리 창 크기에 900×800 논리 화면을 비율 유지해 맞추는 계산. 작은 창은 축소, 큰 창은 확대하고 남는 공간은 여백으로 둔다. 0 크기는 입력 거부한다.
- `window_display.hpp`: 초기 창을 주 모니터 크기에 맞춰 설정, resize 때 SFML View/viewport 갱신, 여백 클릭 차단, F11 전체화면과 Escape 복귀를 관리한다. 원래 창 크기와 위치를 저장/복원하고 60 FPS 제한을 적용한다. 키 자동 반복으로 전체화면이 빠르게 왕복하지 않되 기존 이동/문자 키 반복은 유지한다.
- `client.cpp`: 로그인·커마·접속·게임의 공통 이벤트 루프 맨 앞에서 화면 이벤트를 처리한다. 기존 커마는 mapPixelToCoords를 이미 사용하므로 새 View가 클릭 좌표에도 적용된다. 창을 닫은 뒤 그리기 전에 루프를 종료한다. CP949 인코딩과 기존 한글 문자열은 보존했다.

전체화면은 해상도를 강제 변경하는 독점 모드가 아니라 주 모니터의 데스크톱 해상도에 맞춘 테두리 없는 창이다. 재생성 후에도 네트워크 세션과 게임 상태는 그대로 두고 그래픽 View만 재설정한다. 실제 접속 중 전환 검증은 아직 하지 않았다.

## 사용법과 현재 한계

- 창 테두리를 끌거나 최대화하면 내용이 창 안에 맞춰진다.
- F11: 전체화면 ↔ 창 모드. 전체화면에서 Escape: 창으로 복귀한다. 창 모드 게임 화면에서 Escape의 기존 종료 동작은 유지한다.
- 16:9/울트라와이드에는 좌우 여백이 생길 수 있다. 이것은 비율 보호를 위한 의도된 동작이다. 현재 단계는 HUD 재배치/울트라와이드 추가 시야가 아니다.
- 주 모니터 기준이다. 다중 모니터에서 실행 중인 모니터를 추적하는 기능, 고DPI별 글자 크기 설정, 매우 작은 창 가독성은 후속 검증/개선 대상이다.

기존 스타일과 블러/중앙 정렬을 유지하는 데 UI 설계 스킬의 적응 지침을 참고했다. 새로운 시각 스타일을 추가한 작업은 아니다.

## 검증과 다음 작업

클라이언트 Debug/Release 빌드, 전체 24개 회귀, 화면용 SFML fixture, 기존 커마 preview를 실행했다. 화면 fixture는 실제 창 API와 합성 입력을 사용했으며 커마 이미지 출력도 확인했다. 실제 DB 접속/물리 모니터별 테스트와 동일한 증거는 아니다. 서버/DB/프로토콜은 이번 작업에서 바꾸지 않았다.

다음은 지역 ID를 기준으로 마을·필드·실내의 좌표, 시야, 공격, 섹터를 분리하는 설계/구현이다. 그 후 귀환 버튼, 넓은 필드와 청크 데이터, 옷장과 커마 순서로 진행한다. 현재 로드맵 작성은 아직 이 기능들이 구현됐다는 의미가 아니다.
