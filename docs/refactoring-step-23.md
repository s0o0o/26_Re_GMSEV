# 23. 전투 결과 안내와 몬스터 상태 표시 (#25)

기존에는 공격할 수 없는 이유가 표시되지 않았고, 공격 결과와 사망 통지는
공격자에게만 전달됐다. 이번 작업은 서버의 전투 결과를 공격자와 주변 플레이어가
같이 표시하도록 연결한다. 재생성은 AI 작업 수명 관리와 함께 다음 단계로 분리한다.

## 서버 판정과 전달

- `combat_rules.hpp`: 피해량을 남은 HP 이하로 제한하고, 유효한 피해일 때만
  씨앗을 하나 소비한다. 죽은 대상/씨앗 부족/0 이하 피해는 상태를 바꾸지 않는다.
- 공격 요청을 직렬화하고 대상 몬스터의 HP를 잠근다. 입장 정보의 HP 읽기도
  같은 대상 잠금을 사용해 전투와 시야 진입 정보의 순서를 맞춘다.
- 실내 안전 구역, 씨앗 부족, 대상 없음은 전용 피드백 패킷으로 요청자에게 보낸다.
- 피해와 사망은 공격자 및 대상 주변 플레이어에게 전달한다.
  관전자에게도 실제 공격자 ID와 그 공격자의 남은 씨앗 수를 명시한다.
- 사망 시 활동/추격을 중단하고 관찰자의 시야 목록에서도 대상을 제거한다.
- 입장 패킷에 현재/최대 HP를 추가해, 이미 다친 몬스터를 새로 만난 플레이어도
  정확한 초기 HP를 표시한다.

## 클라이언트 표시

`combat_hud.hpp`가 몬스터별 HP, 피격 시간, 피해 숫자와 안내 문구를 관리한다.
몬스터 위에는 HP 막대, 피격 시에는 짧은 테두리와 피해 숫자가 나온다.
실패 안내는 기존 크림색 패널과 갈색 테두리로 가운데 정렬해 2초간 표시한다.

다른 사람의 공격 통지를 받아도 내 씨앗 수를 바꾸지 않는다.
사망 대상은 월드와 근처 몬스터 목록에서 제거하며, 이후 늦게 도착한 이동은 무시한다.
지역을 이동하면 이전 몬스터 표시와 안내를 비운다.

## 검증

- 순수 전투 규칙 검사: 과도한 피해, 씨앗 부족, 0 피해, 죽은 대상 추가 타격.
- 동일 잠금 패턴에서 16개 공격 요청으로 사망 1회/씨앗 1회 소비 확인.
- 송신 패킷의 공격자/씨앗/HP와 피드백 이유 검증. 잘못된 이유 값은 거부.
- 입장 패킷의 현재 HP, 죽은 몬스터 입장 차단 검사.
- 실제 클라이언트 패킷 처리: 관전자/본인 씨앗 분리, HP 반영, 사망 제거,
  사망 뒤 이동 무시를 검사하고 SFML 전투 안내 화면을 렌더링했다.
- 회귀 테스트 12개, 로그인 모의 서버 검사, 서버·클라·스트레스 도구의
  Debug/Release 빌드 통과. 기존 빌드 경고는 남아 있다.

실제 DB 접속과 여러 클라이언트가 연결된 전투 플레이는 검증하지 않았다.
이번 잠금은 전투 HP 판정 범위이며 서버의 모든 AI/레지스트리 경쟁을 해결한 것은 아니다.
입장 패킷 구조가 바뀌었으므로 서버·클라·스트레스 도구를 모두 새 빌드로 실행해야 한다.
