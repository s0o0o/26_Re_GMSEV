## 문제와 변경

이전 혼합 부하는15초였고 콘솔 실행기 상한은30초였다. 유지 시간만 늘리면 자동 실행의70초 외부 제한이 먼저 프로세스를 끊고 도표에는15초로 잘못 표시되는 문제가 있었다.

`bounded_load.cpp`는2~300초만 허용한다. `run-approved-load.ps1`의 HoldSeconds 기본은 기존15초이며 외부 제한은45초 로그인+유지시간+15초 여유다. 내부 로그인45초/종료drain5초/이동주기는 변경하지 않는다. `render-load-report.ps1`는 실행 로그의 hold_seconds를 읽어 도표를 표시한다. 생산 게임 서버/클라/패킷/DB스키마 수정은 없다.

`bounded_load_test.cpp`는2/30/120/300 허용과1/301/음수/overflow 거부를 검사한다. `tests/load_runner_options_test.ps1`는 파라미터 범위/기본15초와 잘못된 입력이 DB/프로세스 이전에 거부됨을 검사한다.

## 실행 기록

실제 검사 전 두 승인 범위를 각각 COUNT300 확인. 사용 범위는900001000~900001299 기존300개이며 로그인/이동/종료 저장을 수행한다. 신규계정/삭제 없음. 모의TCP300명 및 실패 경계 회귀 통과, 콘솔실행기 /W4·서버Release 최신 빌드 통과.

첫 서버 재빌드 시 이전 실제 UI 검증에서 띄운 소유서버9940이 exe를 잡고 있어 LNK1104가 발생했다. 경로와 소유 기록 확인 후 해당 프로세스만 종료하고 solution Release 재빌드 성공. 초기 프로젝트 직접 빌드는 프로젝트 내부 출력 경로였으므로 실제 부하에는 solution이 생성한 실행파일을 사용했다. 처음 PowerShell 검사에서 비공개 예외 타입 catch가 실패하여 공개 오류ID 검사로 고친 뒤 재실행했다.

## 실제 결과

| 조건 | 로그인/120초 유지/이동응답 | 종료 EOF | drain | 총시간 |
| --- | --- | --- | --- | --- |
| trace ON | 300 / 300 / 300 | 300 | 4512ms | 129836ms |
| trace OFF | 300 / 300 / 300 | 300 | 448ms | 125615ms |

양쪽 클라 거절/전송/프로토콜/timeout0, 서버송신실패0. ON은 서버trace EOF300/저장성공반환300/실패0. OFF는 상세trace 없으므로 개별 저장성공을 확인했다고 확대하지 않는다. 두 범위 각각300 보존을 후검사했다. 37개 전체 회귀는 재실행하지 않았고 수정 범위의 모의TCP회귀/시간옵션 검사를 실행했다.

ON의 로그인수신→ready최대1026ms, 완료큐68ms, world_wait최대2353ms. 측정종료 시 미응답 이동차이 ON1035/OFF40을 관측했다. 이는 종료 시점의 누적차이이며 패킷손실 확정이나 모든 명령 지연 측정이 아니다. trace overhead/주변 OS 상태를 통제한 반복 실험이 아니므로 양쪽 차이의 원인을 확정하지 않는다. 5초 drain 제한 안이지만 ON의4.51초는 여유가 작아 #41잔여 계측으로 남긴다.
