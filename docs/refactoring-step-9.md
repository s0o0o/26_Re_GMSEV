# 9단계: 부하테스트 접속 시도 상한과 통계

이슈: https://github.com/s0o0o/26_Re_GMSEV/issues/11

## 변경

기존에는 최대 10000명 동접/20000개 시도 슬롯까지 증가할 수 있었다.
이제 기본 접속 시도 상한은 30회다. GMSEV_LOAD_ATTEMPTS 환경변수로
1~10000회 범위를 지정할 수 있다. 값이 비었거나 숫자가 아니거나 범위를
벗어나면 30회로 돌아간다. 시작할 때 적용된 상한을 [LOAD] 로그로 출력한다.

상한은 성공한 동접 수가 아닌 누적 시도 수다. 예를 들어 30회 중 5회가
실패하면 동접이 25명이더라도 추가 접속을 시도하지 않는다. 기존 지연 기반
증가 제한도 유지하므로 높은 지연이 측정되면 상한보다 먼저 멈출 수 있다.
상한에 도달해도 연결과 이동은 유지하며 프로그램이 자동 종료되지는 않는다.

화면에 시도/상한, 누적 로그인 성공/거절, 닫힌 소켓, 통신 오류를 추가했다.
기존 STRESS TEST 수치는 현재 로그인된 연결 수다. Closed는 로그아웃 수가
아니라 클라이언트가 정리한 소켓 수로, 로그인 전 실패도 포함한다.
오류 수는 이벤트 수이며 한 연결에서 여러 번 집계될 수 있다.
각 통계는 atomic 값의 개별 스냅샷이어서 실행 중 모든 숫자가 한 시점의
정확한 관계를 보장하지는 않는다. 프로그램을 다시 시작하면 초기화된다.

네트워크 테스트 루프에는 1ms 휴식을 추가해 유휴 시 바쁜 반복을 줄였다.
IOCP 연결 등록 실패도 정리하도록 했다. 설정 파싱은 load_test_config.hpp로
분리했고 다른 컴퓨터에서도 같은 입력으로 시험할 수 있다.

## 실행 방법

서버와 스트레스 도구를 먼저 최신으로 빌드하고, 테스트용 DB에서 실행한다.
기존 계정의 위치/능력치를 변경하고 신규 계정을 생성할 수 있다.
저장소 루트의 PowerShell에서:

```powershell
$env:GMSEV_LOAD_ATTEMPTS = '30'
& '.\stress_test\x64\Release\STRESS_TEST.exe'
```

창을 닫고 다음 실행에서는 설정을 100으로 바꾼다.

```powershell
$env:GMSEV_LOAD_ATTEMPTS = '100'
& '.\stress_test\x64\Release\STRESS_TEST.exe'
```

이 설정은 해당 PowerShell에서 실행한 자식 프로세스에 전달된다.
Visual Studio에서 실행하면 디버깅 환경 설정에 GMSEV_LOAD_ATTEMPTS=100을
넣어야 한다. 설정이 없으면 기본 30회다. 계정 ID는 여전히 시도 슬롯 번호다.

## 검증

tests/load_test_config_test.cpp에서 1/30/100/10000, 잘못된 값과 정수 범위
초과를 검사한다. tests/stress_error_test.cpp에서 실제 접속 함수가 상한에
도달했을 때 추가 시도를 하지 않는지, 성공/거절/종료 통계를 검사한다.
실제 서버나 DB에 접속하는 테스트는 아니다.

스트레스 도구 Debug/Release 빌드로 표시부와 네트워크 연결을 검증한다.
30명/100명 실제 동접 재현, 장시간 안정성, 종료 절차 개선은 포함하지 않는다.
