# 27단계: 늦은 비동기 완료와 재접속 격리

이슈 [#29](https://github.com/s0o0o/26_Re_GMSEV/issues/29), [사전 명세와 검증 결과](specs/async-session-lifetime.md).

## 문제와 변경 흐름

예전에는 `게임 접속 ID → 현재 registry 객체`를 다시 찾아 수신/로그인 완료와 오류를 처리했다. 수신 OVERLAPPED도 세션 내부에 있어 ID 재사용 시 이전 객체 메모리와 새 접속을 혼동할 여지가 있었다.

이제 `송수신 작업 → 원래 접속 owner → 완료 판정 → 원래 객체만 처리 → 작업 해제`로 흐른다.

- `iocp_operation.hpp`: 작업이 원래 접속 shared_ptr를 가진다. OS에 넘긴 메모리는 완료 처리 전까지 살아 있다.
- `game_session.cpp/.hpp`: 수신은 작업마다 별도 heap 버퍼를 사용한다. 내부 `_recvOver`는 미완성 패킷 보관용으로만 남긴다. 등록/close를 잠금으로 직렬화하고, 동시 중복 RECV는 거부한다. 실제 비동기 접속은 shared_ptr 소유가 필요하다.
- `session_completion.hpp`: 종료한 접속 완료는 무시하며, 오류·0바이트·전송 실패는 원래 접속의 정리 대상으로 판정한다. 숫자 key로 새 객체를 찾지 않는다.
- `myserver.cpp`: RECV/SEND/LOGIN 완료를 원래 owner로 고정하고 같은 접속의 완료/종료를 직렬화한다. 작업은 RAII로 한 번 해제한다. 즉시 제출 실패는 완료가 없으므로 제출 함수에서 해제한다. 오류 로그에는 세션 ID·접속 번호·오류 코드를 남긴다.

## 검증

사전 명세 커밋 `39e98dd` → 구현 → AC별 검증 순서로 진행했다. 회귀 16개, 실제 IOCP 수명 테스트 단독 10회(추가 취소/ID 재사용 200회), 서버 x64 Debug·Release, DB 없는 startup-check 통과. 기존 빌드 경고 유지.

실제 DB/게임 창/장시간 부하, 전체 worker를 통과하는 로그인 파서 E2E는 실행하지 않았다. 테스트가 직접 fragment 보관과 완료 판정을 호출하는 경계는 명세에 명시했다. 클라이언트와 공유 프로토콜 변경은 없다.

문서 검증: 변경 Markdown의 엄격한 UTF-8 디코딩과 상대 파일 링크 존재 확인, `git diff --check` 통과. 기존 CP949 서버 소스는 인코딩을 유지했다.
