# 6단계: 서버 DB 모듈 분리

이슈: https://github.com/s0o0o/26_Re_GMSEV/issues/8

## 무엇을 바꿨나

myserver.cpp에 들어 있던 DB 접속, 종료, 오류 진단, 캐릭터 조회, 신규 생성,
능력치 저장 코드를 game_database.cpp로 옮겼다. 게임 쪽에서 사용하는 함수는
game_database.hpp에 선언했다. Visual Studio 프로젝트에도 두 파일을 등록했다.

DB 연결 핸들 henv/hdbc와 오류 진단 함수는 익명 namespace 안에 둬서
다른 cpp에서 직접 접근할 수 없게 했다. 헤더에는 Windows/ODBC 타입을
노출하지 않는다. game_database.cpp가 ODBC 라이브러리 링크를 명시한다.

## 로그인 흐름을 읽는 방법

1. myserver.cpp에서 로그인 패킷의 계정 ID와 닉네임을 검증한다.
2. get_DB_login_info(...)를 호출한다.
3. 이제 game_database.cpp가 기존 저장 프로시저 get_user_info로 조회한다.
4. 기존 흐름대로 조회 실패 시 insert_new_user(...)를 호출하고 다시 조회한다.
5. myserver.cpp가 조회 결과를 session->object에 채우고 로그인 완료를 알린다.

게임 쪽에서는 “언제 캐릭터를 조회하고 저장하는가”를 읽고,
DB 파일에서는 “어떤 SQL과 컬럼으로 조회하고 저장하는가”를 읽으면 된다.
기존 함수 이름과 인자는 유지했다. 여러 출력 인자를 PlayerRecord 같은
데이터 타입으로 바꾸는 것은 별도 단계에서 진행할 수 있다.

## 이번 범위

SQL, DSN, 테이블, 신규 캐릭터 기본값, 로그인 및 저장 정책은 유지했다.
실행 중인 DB의 데이터나 스키마는 변경하지 않았다. 이번은 모듈 경계를
만드는 작업이며 DB 연결 클래스를 도입하거나 쿼리 오류를 수정한 단계는 아니다.

현재 남은 문제도 있다.

- 조회 결과의 “계정 없음”과 “DB 오류”가 모두 false라 신규 생성 시도를 구분하지 못한다.
- 여러 작업 스레드가 하나의 연결과 트랜잭션을 공유한다.
- 일부 ODBC 호출 결과를 검사하지 않고, 연결 실패 시 핸들 정리가 부족하다.
- update_user_info의 damage와 insert_new_user의 name 인자는 실제 SQL에 반영되지 않는다.
- finalizeDB는 선언/구현되어 있지만 서버 종료 흐름에서 호출되지 않는다.

모듈 분리로 위 문제가 해결되지는 않는다. 특히 서버 작업 스레드의 종료
절차 없이 임의로 연결을 닫으면 진행 중인 쿼리와 충돌할 수 있다.

## 검증

서버 x64 Debug와 Release 빌드로 새 cpp의 컴파일 및 함수 링크를 확인했다.
기존 정수 변환 C4244와 런타임 라이브러리 충돌 LNK4098 경고는 남아 있다.
실제 DB 접속·생성·저장 쿼리를 실행하는 검증은 하지 않았다.
