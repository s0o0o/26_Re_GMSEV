# 10단계: 햄스터 외형 선택 1단계

이슈: https://github.com/s0o0o/26_Re_GMSEV/issues/13

## 이번에 가능한 것

로그인 전에 Golden/Cream/Cocoa/Silver/Rose 5가지 털 색상을 선택하고
4방향의 큰 캐릭터 미리보기를 확인한다. 기존 숫자 ID → 닉네임 → 로그인
흐름을 사용하며 로그인 전 색상을 고르면 게임 속 캐릭터에도 적용한다.

- 색상 칸 클릭 또는 좌/우 방향키: 털 색상 선택
- 위/아래 방향키: 미리보기 방향 전환
- Enter: 기존 로그인 입력 단계 진행

미리보기 회전은 게임 속 초기 방향을 바꾸지 않는다. 선택한 색은 이번 접속
동안 서버에 보관되며 다른 클라이언트에도 전달된다. DB 영구 저장과 중도
외형 변경은 이번 범위가 아니다. 프로그램 재시작 시 기본 금색으로 시작한다.

## 코드 흐름

기존 character.png는 48x48 캐릭터 4방향을 합친 192x48 이미지다.
몸/눈/옷 레이어가 분리되어 있지 않다. 이미지 파일 자체는 바꾸지 않고
hamster_customizer.cpp가 노란 털 영역을 골라 색상별 텍스처 5개를 만든다.
흰 배, 눈, 분홍 귀, 짙은 윤곽선은 유지한다. 색 영역 판정은 이 원본 이미지의
팔레트에 맞춘 것이므로 다른 캐릭터 이미지로 교체하면 다시 검토해야 한다.

HamsterCustomizer가 텍스처들을 계속 소유한다. 게임 객체의 스프라이트는
그 텍스처를 참조하므로 임시 지역 텍스처를 가리켜 사라지는 문제가 없다.
client.cpp에는 이벤트 전달·화면 호출·선택값 적용만 연결했다.

1. cs_packet_login.fur_color로 선택한 색상 번호를 보낸다.
2. 서버가 0~4 범위를 검사하고 GameObjectState._furColor에 저장한다.
3. 본인 sc_packet_avatar_info와 타인 sc_packet_enter에 색상 번호를 담는다.
4. 클라이언트가 같은 색상 텍스처를 적용한다. 잘못된 번호는 기본색으로 표시한다.

패킷 크기가 바뀌었으므로 서버·클라이언트·스트레스 도구를 모두 최신으로
빌드해야 한다. 예전 실행 파일은 호환되지 않는다. 스트레스 도구의 기본색은 0이다.

## 눈 모양과 의상은 다음 단계

눈 모양/옷을 임의로 덧칠하면 옆모습과 뒷모습에서 위치가 맞지 않는다.
다음 단계에서는 4방향 눈/옷 레이어, 기본 몸체와의 정렬 기준, 선택 가능한
리소스를 준비하고 지금의 외형 데이터에 항목을 추가할 수 있다.
현재 기능을 눈 모양/의상 선택까지 완료한 것으로 보면 안 된다.

## 검증

- 서버·클라이언트·스트레스 도구 x64 Release 빌드 통과.
- tests/run-regressions.cmd의 회귀 프로그램 6개 통과.
- 패킷 테스트에 본인/타인의 색상 전송과 번호 범위 검사를 추가했다.
- tests/run-customizer-preview.cmd가 SFML로 5색 미리보기를 렌더링한다.
  선택 순환, 투명도, 회색조 픽셀 보존, 실제 털 영역 변화와 잘못된 번호를 검사한다.
- build/tests/hamster-preview-0.png부터 4.png가 미리보기 결과다.
  생성물은 Git에 포함하지 않는다. 이 테스트는 OpenGL 컨텍스트가 필요하다.
- 다중 클라이언트 실제 접속과 한글 IME 검증은 미실시다.

시각 테스트는 SFML NuGet 패키지가 복원된 상태에서 x64 Native Tools Command
Prompt로 실행한다. 원본 이미지와 폰트 로드 실패 시 클라이언트는 오류로 종료한다.
