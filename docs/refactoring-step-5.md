# 5단계: 로그인 ID와 닉네임 설정

이슈: https://github.com/s0o0o/26_Re_GMSEV/issues/7

## 확인한 기존 상태

이전 닉네임 입력 수정은 작업 파일에만 있었고 커밋되지 않았다.
한글/영어 입력과 UTF-8 표시 코드는 있었지만, 입력한 이름을 해시해서
DB의 숫자 계정 ID로 변환했다. 서로 다른 이름 또는 숫자 ID와 해시 결과가
겹치면 같은 캐릭터를 조회할 수 있었다.

이번 커밋은 이전 닉네임 변경을 포함해 정리하고 해당 해시 변환을 제거한다.

## 사용법

1. 로그인 화면에서 숫자 계정 ID를 입력하고 Enter를 누른다.
2. 같은 입력 위치에서 닉네임을 입력하고 Enter를 누르면 접속한다.
3. 닉네임 입력 중 Esc를 누르면 계정 ID 입력 단계로 돌아간다.
4. Backspace는 현재 단계 입력을 지운다.

예: 계정 ID `321`, 닉네임 `햄찌`를 입력하면 DB에서는 ID 321의 캐릭터를
조회하고, 게임에서는 이름을 햄찌로 표시한다. 다음 접속에서 같은 ID와
다른 닉네임을 사용해도 같은 캐릭터를 조회한다.

닉네임은 1~12자, 영어/숫자/밑줄/한글 음절·자모를 허용한다.
공백과 다른 특수문자는 받지 않는다. 기존 숫자 ID는 0~2147483647 범위이며
앞자리 0은 같은 숫자 계정으로 취급한다.

## 코드 흐름

- client.cpp: 계정 ID 단계와 닉네임 단계를 구분한다. 안내 문구를 추가했다.
- shared/login_input.hpp: 숫자 범위와 UTF-8 닉네임 규칙을 검증한다.
- cs_packet_login.inputId: DB 조회용 숫자 계정 ID를 전달한다.
- cs_packet_login.name: 닉네임 UTF-8 바이트를 전달한다.
- myserver.cpp: DB 접근 전에 이름과 ID를 검사하고, 성공 시 object._name에 이름을 저장한다.
- 클라이언트: 내 이름과 다른 캐릭터 이름을 UTF-8에서 SFML 문자열로 변환해 표시한다.

서버는 이름의 null 종료, 잘린 UTF-8, 잘못된 바이트, 글자 수와 허용 문자를
검사한다. 클라이언트 검사만 믿지 않는다.

## 범위

닉네임은 이번 접속의 표시 이름이며 DB에 영구 저장하지 않는다.
중복 닉네임도 허용한다. 닉네임 중복 금지와 영구 저장은 DB 스키마 및
계정 정책을 함께 정해야 한다. 현재 로그인은 비밀번호 인증이 없는 기존
방식이므로 숫자 ID를 아는 사람의 접속을 막는 인증 기능은 아니다.

기존 해시 방식으로 접속했던 영문/한글 계정의 데이터는 자동 이전하지 않는다.
기존에 숫자로 로그인했던 캐릭터는 같은 숫자 ID로 접속한다.
한글은 SFML TextEntered 이벤트로 전달된 문자를 받으므로 Windows IME의
조합·확정 동작은 실제 실행 환경에서 확인해야 한다.

닉네임 버퍼가 48바이트로 확장되었으므로 서버·클라이언트·스트레스 도구를
함께 재빌드해야 한다. 예전 실행 파일과 섞어 사용하면 패킷 크기가 다르다.

## 테스트

tests/login_input_test.cpp는 정수 범위, 한글 UTF-8, 이름 길이, 잘린 문자열,
잘못된 인코딩과 허용하지 않는 문자를 검사한다. x64 Native Tools Command
Prompt에서 루트 기준으로 실행한다.

```bat
cl /nologo /EHsc /std:c++17 tests\login_input_test.cpp /Fe:TP_2023192003\x64\Debug\login_input_test.exe /Fo:TP_2023192003\x64\Debug\
TP_2023192003\x64\Debug\login_input_test.exe
```

NDEBUG를 정의하지 않아야 assert 검사가 실행된다. 실제 접속과 한글 IME
입력은 자동 테스트에 포함하지 않는다.

검증 결과: 로그인 입력 테스트 통과. 서버·클라이언트·스트레스 도구의
x64 Release 빌드 성공. 기존 정수 변환, 클라이언트 중간 디렉터리 공유,
서버 런타임 라이브러리 충돌 경고는 남아 있다.
