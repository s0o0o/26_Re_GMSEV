# 50단계 — 넓은 필드 청크·충돌·가시 렌더

2026-11-16, #54. [사전 명세·완료 기준](specs/field-chunks.md), [현재 구조](architecture/field-chunks.md).

기존 필드는20×18 배경과 전체 map_data 배열이었다. 이제 공용 거점24×18을 유지하고 SunnyPeak는256×256이다. 기존 시작 구역 동쪽 통로로 넓은 초원·강의 다리·절벽 통로가 이어진다. 지형과 충돌이 같은 shared 자료를 사용하며 단순 크기 상수 확대가 아니다.

서버는16×16 지형 청크를 최대16개 캐시하고, 수집 상태는 캐시와 분리한다. 클라는 원본 픽셀 시트로 화면에 보이는 최대6청크·288타일만 그린다. 화면 밖 캐릭터는 한 칸 여유로 제외하고, A*는 기본1024확장 예산으로 제한한다. DB codec은 유지하지만 지역 범위가 달라져 프로토콜은v4다. 모든 서버/클라/도구를 함께 빌드한다.

실행 검증: 전65,536칸 지형/서버 충돌 일치, 통행 가능62,640칸 전체의 시작점 연결 BFS, 캐시 퇴거/수집 상태/리스폰/끝 좌표/경로 예산 검사. 실제 TCP/IOCP4worker+DB 대역에서 청크 경계·실제 다리 통과·물/외곽 충돌·NPC활성/수면·귀환·저장·v3로그인 거절을 검사했다. 전체43회귀, 서버/native/GUI Debug·Release6빌드, DB/네트워크 없는 Release --startup-check, native/로그인/화면 크기 GPU검사 통과. 최초 작은 카메라 기대값 실패를 새 범위와 안전한 fixture 배열 경계에 맞게 고친 후 재실행했다.

미리보기 field-scenes.png, field-view-0~3.png, field-collision-preview.png, field-1280x720.png, field-800x900.png는 생산 렌더러 테스트 출력이다. 실제 OS/DB 캡처가 아니다. 독립 UI 검토는 **ship — 기반 단계 범위 한정**이다. 기존 자산·캐릭터 크기·UI를 유지했고 원치 않는 그림자 조각 반복을 제거했다. 원본 파일/새 raster 생성은 없다.

한계: 완성된 탐험 콘텐츠·세밀한 아트·FPS/혼잡 장면·실제 DB 장시간 부하를 입증하지 않는다. 기존3적·3주민의 행동을 유지했으며 대량 NPC를 새로 배치하지 않았다. #10/#41은 별도 관측 상태를 유지한다.

다음은 클럽하우스 옷장·커스터마이징 확장이다. 새 DB 권한을 임의로 사용하지 않고 현재 저장 계약에서 가능한 범위를 먼저 확인한다.
