# 41단계: 플레이어 월드 크기와 픽셀 비율

작업 [#45](https://github.com/s0o0o/26_Re_GMSEV/issues/45), [명세/검증](specs/world-character-scale.md). 부하 큐 이슈#41과는 별개인 화면 수정이다.

## 왜 다른 캐릭터보다 커 보였나?

플레이어 아틀라스는 원본을 약1.25배로 확대해48×48 프레임에 넣었다. `client.cpp`가 이것을 다시2배로 그려 원본 대비약2.5배가 됐다. 주민은 원본을2배로 그렸으므로 플레이어만 상대적으로 컸다. 중간1.25배 최근접 확대 때문에 픽셀의 반복 폭도 균일하지 않았다.

## 무엇을 바꿨나?

- `world_character.hpp`: 중간 확대에서 각 원본픽셀의 대표샘플을 골라 월드 전용48프레임을 복원한다. 필터로 뭉개거나PNG를 재작성하지 않는다. 기본8프레임을 원본 시트와 대조했다.
- `hamster_customizer.cpp/.hpp`: 기존 커마/로딩용 텍스처는 그대로 두고,90외형의 월드용 텍스처를 로딩 때 별도로 보관한다. 매 프레임 GPU이미지를 읽거나 크기변환을 반복하지 않는다.
- `client.cpp`: 본인·다른 플레이어가 모두 월드용 텍스처와 정수2배를 사용한다. 발 기준도y46으로 통일했다. 화면상 가로·세로는 기존보다 약20% 작아졌지만 이동/충돌/타일 좌표는 동일하다.
- 이름표:30에서16으로 줄이고 새 머리 위치 위에 가운데 정렬했다. 같은 칸의 여러 캐릭터와 이름표가 겹치는 기능까지 해결한 것은 아니다.
- 월드preview fixture들도 같은 텍스처/발기준을 사용하도록 맞췄다. 커마preview는 큰 UI 표시를 유지한다.

배경은 기존50/16배로 렌더한다. 이번에는 캐릭터끼리 원본픽셀2배를 통일하고 배경과의 크기 비율을 조정했다. 전체화면이나 임의 창 크기의 모든 물리픽셀을 정수배로 맞춘 작업은 아니다. 맵 자체를 바꾸면 충돌/시야도 영향을 받으므로 범위에서 제외했다.

## 실제 확인

기존 승인계정으로 실제DB/서버에 관찰자1명+다른 플레이어20명을 접속했다. 패킷으로20명/서로 다른12타일을 관측했고20초 유지/EOF20을 확인했다. 생산클라 코드 테스트 창에서 저장한 `build/tests/live-multiplayer-scene.png`를 확인했다. 기존 장면은 `build/tests/live-multiplayer-scene-before-scale.png`에 보존했다. 위치·카메라가 다른 실행이므로 정량적인 동일프레임 전후 비교는 아니다.

클라Debug/Release, 기본회귀36개,8프레임 원본alpha/보이는RGB·90외형 검사, 커마·창크기/전체화면·로그인·주민·지역GPU 회귀를 통과했다. 자동디자인검출기는 C++경로오류로 실패했고 실제 렌더와 검사로 확인했다. CP949 유지, 원본PNG 변경 없음. impeccable 스킬의 기존스타일 보존·렌더확인 원칙에 따라 커마/배경을 전면개편하지 않고 월드표시만 분리했다.

다음은 기존 P1 [#41](https://github.com/s0o0o/26_Re_GMSEV/issues/41)의 로그인·대량이동 완료 큐 지연 개선이다. 이번 화면수정으로 그 부하문제를 고쳤다고 보고하지 않는다.
