# 26단계: 가벼운 SDD 문서 도입

이슈: [#28](https://github.com/s0o0o/26_Re_GMSEV/issues/28)

## 무엇을 바꿨나

채팅과 단계별 작업 설명만으로는 구현 전 합의한 목표와 테스트가 보장하는 범위를 찾기 어려웠다. 이제 [SDD 절차](sdd.md)와 [템플릿](specs/_template.md)으로 목적·범위·영향·오류·완료 기준·작업·검증 결과를 한 명세에 연결한다.

`AGENTS.md`와 [기존 작업 절차](development-workflow.md)에 연결했다. 작은 오탈자/정렬 수정에는 새 명세를 강제하지 않는다. GitHub 이슈·브랜치·한국어 커밋·main 병합 규칙은 유지한다. 외부 도구 설치, 게임 소스·테스트 변경은 없다.

첫 사례 [세션·월드 명세](specs/session-world-lifecycle.md)는 기존 #26/#27 작업의 **사후 명세**다. 실제 코드·테스트를 확인해 AC-01~06과 연결했고, 테스트 집합 콜백/송신 캡처/TCP loopback을 실제 DB·전체 서버·화면 검증과 구분했다.

## 이번 문서 도입 완료 기준

- DOC-01: 절차와 템플릿에 목적, 포함/제외, 현재/목표, 서버/클라/프로토콜 영향, 오류·경계, 관찰 가능한 AC와 검증 항목이 있다.
- DOC-02: 첫 사례가 실제 구현·테스트 경로에 연결되고 미검증 사항을 명시한다.
- DOC-03: AGENTS·기존 절차에서 명세에 도달하고, 작은 수정 면제와 기존 Git 규칙이 유지된다.
- DOC-04: 변경 문서는 UTF-8이며 상대 파일 링크가 유효하고 `git diff --check`가 통과한다.

## 검증 결과 (2026-10-28)

- DOC-01/02/03: 템플릿 필수 절과 AC-01~06의 작업/테스트 연결을 확인했고, 실제 이벤트·종료·재생성 구현 및 테스트 소스를 읽어 표현을 대조했다. 이는 문서/코드 확인이지 전체 서버 실행 검증이 아니다.
- DOC-04: PowerShell에서 엄격한 UTF-8 디코딩, Markdown 상대 파일 링크의 `Test-Path`, 템플릿 필수 절과 AC ID 참조 검사를 수행했다. 변경 문서 7개와 상대 파일 링크 25개 통과. `git diff --check` 통과.
- Windows x64 MSVC 환경에서 기존 `tests\run-regressions.cmd`를 실행해 15개 프로그램 모두 통과했다. 기준 게임 코드는 `18a9aea`이며 이번 브랜치는 문서만 변경했다. AC-01~06의 제한된 테스트 경로를 재확인한 결과다.
- 서버/클라이언트/스트레스 솔루션 빌드, 실제 DB, 전체 서버 worker/timer, 게임 창 다중 실행과 부하테스트는 이번에 실행하지 않았다. 과거 빌드 결과는 첫 명세에서 과거 기록으로만 인용했다.
