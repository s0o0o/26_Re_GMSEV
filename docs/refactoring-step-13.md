# 13. 햄토리·비쥬 선택 (#16)

## 무엇을 바꿨나

기존 커스터마이저는 한 캐릭터의 색/눈/목도리만 바꿀 수 있었다.
제공받은 두 시트에서 4방향 정지 포즈를 추출하고 캐릭터 선택을 추가했다.
배경 블러와 로그인 입력 → 커마 → 서버 접속 흐름은 유지했다.

- `hamster_customizer.cpp/.hpp`: 두 캐릭터 리소스를 읽고 선택 버튼/F5 처리.
  캐릭터 2 × 털색 5 × 눈 3 × 목도리 3 = 90가지 조합을 준비한다.
- `shared/appearance.hpp`, `shared/protocol.hpp`: 캐릭터 종류와 허용 범위 정의,
  로그인/본인 정보/다른 플레이어 입장 패킷에 `character_kind` 추가.
- `client.cpp`: 선택한 종류를 로그인 패킷에 넣고, 받은 종류로 본인과 타인을 그린다.
- 서버 `game_object.hpp`, `myserver.cpp`, `session_packets.cpp`: 잘못된 종류 거부,
  세션에 선택 보관, 다른 클라이언트에도 전송.
- `tools/extract_character_sheets.cpp`, `tools/rebuild-character-resources.cmd`:
  원본 시트로부터 재현 가능한 리소스 생성. 오른쪽 포즈는 왼쪽의 좌우 반전이다.

## 사용 방법과 제한

ID/닉네임 입력 후 커마에서 Hamtaro/Bijou 버튼 또는 F5로 선택한다.
색/눈/목도리를 정하고 Connect를 누르면 그때 서버에 연결한다.
외형은 세션에만 보관하며 DB 영구 저장은 이번 범위에 포함하지 않았다.
정지 포즈 4방향만 추출했으며 걷기 프레임 애니메이션은 추가하지 않았다.
패킷 구조가 변경되므로 서버·클라이언트·스트레스 도구를 모두 재빌드해야 한다.

원본/출처/추출 좌표는 `assets/characters/README.md`에 기록했다.
다운로드 원본과 기존 캐릭터 이미지는 보존했다.

## 검증

- 커스터마이저 미리보기: 90조합 크기/투명도, 기본 조합 원본 일치,
  F5 전환과 잘못된 종류 처리 확인.
- 실제 클라이언트 화면 렌더링: 블러 배경과 비쥬 선택, 뒤로 가기/실패 후 선택 유지 확인.
- 회귀 테스트 7개 통과: 로그인 흐름/입력/조회, 부하 설정, 경로 탐색,
  패킷 종류 전달, 스트레스 오류 처리.
- 서버·클라이언트·스트레스 도구 Release x64 빌드 결과는 이슈의 완료 기록 참고.
- 실제 DB 접속 및 다중 클라이언트 동시 접속은 실행하지 않았다.
