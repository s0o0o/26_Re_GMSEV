# 21. Sunny Peak 야외 왕복 (#23)

## 이동 흐름

클럽하우스 거실 아래쪽 금색 발판 (10,14)에 들어가면 Sunny Peak (42,10)에 도착한다.
야외 금색 발판 (42,12)에 들어가면 실내 (10,12)로 돌아온다.
도착점과 발판을 분리해 연속 자동 왕복을 막았다. 금색 발판은 HUD 위에서 보이는
위치로 잡았다. 기존 문/계단은 아직 포털이 아니다.

## 코드 구조

- `shared/world_layout.hpp`: 실내/야외 충돌, 포털 쌍, 안전 좌표, 카메라 경계를 정의.
  기존 실내 충돌 정의는 유지한다.
- 야외는 20×18칸. 월드 x=32부터 배치하고 실내와 사이 공간을 막는다.
  전체 좌표 배열은 52×18이다. 별도 mapId를 도입한 범용 맵 엔진은 아니며,
  작은 두 구역을 기존 좌표/섹터/가시성 시스템에 얹은 첫 단계다.
- 서버 `C2S_P_MOVE`: 통과 가능한 이동 후 포털 도착 좌표로 바꾸고 기존
  섹터/관심목록 갱신과 이동 응답을 사용한다. 클라가 이동 목적지를 결정하지 않는다.
- 로그인 시 정상 야외 좌표는 보존하고 잘못된 좌표는 실내 시작점으로 보정한다.
- 클라 `clubhouse_renderer.hpp`: Sunny Peak 원본의 (921,1,320,288)을 추출해
  야외 배경으로 사용. 원본 및 크레딧은 보존한다.
- 클라가 서버에서 받은 본인 좌표에 따라 배경을 바꾸고 카메라를 해당 구역
  범위로 제한한다. 지역명/금색 발판 이동 안내를 표시한다.

## 검증

- 야외 배경/선택 캐릭터/지역 안내 실제 SFML 렌더링 확인.
- 양방향 포털의 안전한 도착점, 즉시 재이동 방지, 야외 좌표 보존 검사.
- BFS로 야외 모든 통과 가능 칸의 연결성 확인. 구역 사이 통과 차단 검사.
- 실제 클라 이동 패킷 처리에 야외/실내 좌표를 넣어 아바타·카메라 전환 확인.
- 회귀 테스트 11개와 로그인 소켓 모의 테스트 통과.
- 서버·클라 Debug/Release 빌드 결과를 이슈 완료 기록에 남긴다.
- 실제 DB 로그인/실제 서버 다중 접속/포털 플레이 테스트는 실행하지 않았다.

Sunny Peak 전체 장면을 연결한 것은 아니고 숲 공터 한 장면을 사용했다.
구멍은 현재 장식이며 피해/낙하 효과가 없다. 야외 몬스터·채집물은 아직 없고
서버는 두 지역 모두 탐험 프리뷰로 몬스터 수를 0으로 유지한다.
Sunny Cave와 나머지 지역은 다음 단계다. 서버/클라를 모두 새 빌드로 실행한다.
