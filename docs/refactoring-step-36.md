# 36단계: 지역마다 독립된 섹터 저장소

이슈 [#38](https://github.com/s0o0o/26_Re_GMSEV/issues/38), [사전 명세·완료 기준·실행 결과](specs/region-sector-index.md).

## 어디까지 했나

지역 2B의 첫 부분인 **물리적인 지역별 섹터 분리**를 완료했다. 기존 전역 X,Y 상태/패킷/DB 저장 형식은 아직 유지한다. 위치의 location() 변환으로 지역 내부 좌표를 얻어 새 인덱스에 넣는다. 지역 내부 좌표 전송/저장까지 전부 끝냈다는 의미는 아니다.

DB 조회는 `EXEC get_user_info ?`의 9개 결과 열에 의존한다. 해당 저장 프로시저/테이블 DDL은 저장소에 없어 실제 정의와 영향 범위를 확인하지 않은 채 스키마를 바꾸지 않았다. 이번에는 실제 DB에 접속하거나 데이터를 변경하지 않았다.

## 기존 문제와 변경

myserver.cpp의 `sectors[MAX_SECTOR_X][MAX_SECTOR_Y]`는 전체 맵을 하나의 격자로 관리했다. 검색 후 region을 검사하므로 논리적 격리는 있었지만 저장소는 분리되지 않았다. 포털/로그인/주민/몬스터가 배열에 직접 넣고, 접속 종료는 전체 격자를 훑으며 ID를 지웠다.

새 `region_sector_index.hpp`의 Index는 다음 키를 사용한다.

| 위치 | 지역별 섹터 키 |
| --- | --- |
| 클럽하우스 내부 (10,10) | (Clubhouse,0,0) |
| 필드 내부 (10,10) | (SunnyPeak,0,0) |
| 클럽하우스 내부 (20,16) | (Clubhouse,1,0) |

숫자 좌표와 섹터가 같아도 region이 다르면 다른 bucket이다. 실제 사용 중인 bucket만 만들고 비면 제거한다. 같은 숫자 섹터를 지역 필터로 사후 구분하는 것과 다르다.

- `put(id,position)`: 새 소속 등록과 이전 소속 제거를 하나의 잠금에서 수행한다. 같은 위치 중복 등록은 늘어나지 않는다. 잘못된 갱신은 실패하고 이전 소속은 보존한다.
- `nearby(position,range)`: 해당 지역에서 범위와 교차하는 섹터 후보만 복사한다. 복사를 끝내 잠금을 푼 후 서버가 registry의 현재 접속/죽음/지역/정확한 거리 조건을 확인한다. 인덱스 잠금 안에서 registry/Lua/네트워크 함수를 호출하지 않는다.
- `remove(id)`: ID→소속 키를 사용해 해당 bucket에서 바로 제거한다. 전체 격자 스캔을 없앴다.
- `snapshot/memberships`: 테스트에서 실제 bucket 내용과 ID별 단일 소속을 확인한다. 컨테이너를 밖에 노출해 직접 수정하지 않는다.

로그인·몬스터/주민 초기화·일반 이동·주민 산책·부활·포털·접속 종료를 새 API로 연결했다. 기존 updateSector(oldX,oldY) 호출 시그니처는 호환을 위해 남겨두었지만, 실제 이전 위치는 호출자가 아닌 인덱스가 보관한다. 전달된 old 좌표를 믿고 직접 배열을 수정하지 않는다.

world→index 잠금 순서를 유지한다. 단일 mutex를 사용하므로 큰 부하에서도 무조건 빨라진다고 보장하지 않으며, 추후 지역/섹터별 잠금 분할은 실제 측정 후 결정한다.

## 검증

단위 검사에서 동일 local 좌표의 두 지역 분리, 경계/범위/invalid 거부, 중복/이동/제거/빈 bucket 정리를 확인했다. 4 writer가 서로 다른 ID와 공용 ID를 번갈아 갱신하는 동안 snapshot reader가 ID 중복을 검사했다. 이것은 동시 실행 회귀이며 sanitizer나 실제 DB 부하는 아니다.

실제 4-worker TCP fixture는 실내 local19→20 경계, 포털, 같은 local (10,10)의 서로 다른 지역, 종료 후 전체 bucket 정리를 확인했다. 만료한 NPC의 실제 부활 서비스도 별도로 실행해 이전 bucket 제거/새 home 등록/ENTER 전달을 확인했다. 기존 주민 산책과 몬스터 전투/접속 수명 검사는 그대로 유지했다.

전체32개 회귀, 서버/클라/스트레스 Debug/Release, DB 없는 startup-check 통과. 인덱스와 sector worker 각각10회 추가 통과, 최종 부활 보강 검사도 통과. 기존 경고는 남아 있다. 실제 DB/고동접/일반 게임 접속 화면은 미검증이며 상세 구분은 명세에 기록했다.

## 미리보기와 다음 작업

`tests/run-region-preview.cmd`가 `build/tests/region-sectors-preview.png`를 만든다. 기존 게임 맵 렌더러와 실제 생산 Index의 계산값을 표시한 **테스트 출력**이다. 화면에 주민/모든 HUD를 그린 일반 게임 캡처가 아니며, 기존 주민이 사라진 것도 아니다. 이번 작업은 맵 그림이나 크기를 바꾸지 않았다.

다음 2B-2는 저장 프로시저/테이블 계약을 확인하고 지역 ID+지역 내부 좌표를 실제 패킷·저장 모델로 전환하는 작업이다. 구버전 클라/스트레스와 섞이지 않도록 버전·오류 처리를 명세하고 기존 좌표의 변환/복구 경계를 검증해야 한다. 실제 DB 마이그레이션 실행은 사전에 영향과 검증 범위를 알린 뒤 진행한다.
