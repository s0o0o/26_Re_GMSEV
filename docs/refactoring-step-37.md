# 37단계: DB 로그인 결과와 지역 위치 저장 경계

이슈 [#39](https://github.com/s0o0o/26_Re_GMSEV/issues/39), [명세·검증](specs/database-position-contract.md), [실제 메타데이터](database-contract.md).

## 기존에는 무엇이 위험했나?

`game_database.cpp`는 프로시저 결과를 순서대로 9개 정수에 넣었다. NULL 확인은 있었지만 열 순서/이름/타입, 요청한 계정과 반환 계정의 일치, 추가 행을 충분히 확인하지 않았다. DB int 스탯을 게임의 SHORT에 넣을 때 범위를 벗어나면 값이 변할 수도 있었다.

`myserver.cpp`에서는 로그인 때 위치를 보정하고 저장 때는 원래 X,Y를 직접 넘겼다. 지역 개념을 확대하려면 위치 변환을 공통 저장 경계에 모아야 했다.

## 어떻게 바뀌었나?

- `database_contract.hpp`: DB 결과를 받는 검사표다. 9열의 의미와 계정·스탯을 검사하고, 정상 한 행인 경우에만 결과를 전달한다.
- `game_database.cpp`: 실제 ODBC 결과를 검사표에 연결한다. 조회 실패/이상 데이터는 로그인 실패이며, 없는 계정으로 오인해 생성하지 않는다.
- `database_position.hpp`: 집의 `(10,10)`과 필드의 `(10,10)`을 구분한다. 현재 DB 형식으로는 각각 `(10,10)`, `(42,10)`으로 저장하고 다시 지역 좌표로 복원한다.
- `game_database.hpp`와 `myserver.cpp`: 로그인/전투/접속 종료의 저장 호출이 지역 위치 검증을 통과하도록 변경했다. DB 작업은 기존처럼 월드 잠금 밖에서 수행한다.

흐름은 **DB 조회 → 결과 계약 검사 → 위치 복원 → 게임 입장 → 지역 위치 검사 → 기존 DB X,Y 저장**이다. 잘못된 신규 저장은 차단하고, 예전의 잘못된 위치는 기존 정책대로 거점으로 복구한다.

## 검증과 한계

실제 DB에는 구조 정보 SELECT만 실행했다. 9개 int 결과와 최대 HP/공격력의 NULL 허용을 확인했다. 현재 권한에서 유일 키가 표시되지 않아 유일성은 미확인이다. 계정 내용은 읽거나 바꾸지 않았다.

회귀 34개, DB 대역 서버 워커 통합 검사, 서버/클라/스트레스 Debug·Release 빌드, DB 없는 서버 초기화와 렌더 테스트를 실행했다. 실제 DB 로그인/저장/동접 검증과 새 지역 컬럼 도입은 이번 완료 범위가 아니다. 아래 이미지는 실제 게임 접속 캡처가 아니라 생산 렌더러·위치 codec 테스트 출력이다.
