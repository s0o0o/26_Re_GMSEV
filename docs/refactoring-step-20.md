# 20. 클럽하우스 시작 방 (#22)

## 기존 구조와 변경

기존 `initializeMap()`은 2000×2000칸을 무작위 지형/효과 아이템으로 채웠다.
이번에는 첨부 클럽하우스 시트 아래층 거실을 고정 배경으로 사용하는 작은
24×18칸 안전 방으로 바꿨다. 리소스 전체를 새로 그리지는 않았다.

- `shared/clubhouse_map.hpp`: 방 크기, 시작 위치 (11,12), 통과 가능 구역 정의.
  벽·패딩·계단·큰 가구는 막는다. 픽셀 단위가 아닌 보수적인 그리드 충돌이다.
- `server_config.hpp`: 서버 월드 배열/섹터/경로 탐색 크기도 24×18로 맞춘다.
- `myserver.cpp`: 랜덤 맵 생성 대신 고정 충돌 데이터를 채운다.
  실내 안전 방에서는 몬스터 생성을 0으로 고정한다. 환경변수의 요청 수량도
  현재 실내에서는 무시하며 로그에 알린다. 랜덤 피해/회복/채집 타일도 없다.
- `game_database.cpp`: 신규 계정 시작 위치를 실내의 안전한 좌표로 지정한다.
  로그인 시 기존 DB 좌표가 방 밖/가구 안이면 세션 좌표를 안전 위치로 보정한다.
  기존 정상 저장 경로가 이후 보정 좌표를 저장하며, SQL 스키마 변경은 없다.
- `clubhouse_renderer.hpp`: 원본 시트의 (505,323,360,274)를 런타임에 추출한다.
  원본 배경색을 제거하고 384×288 캔버스에 배치한다.
  원본 16픽셀 = 한 칸 = 화면 50픽셀. 최근접 확대를 유지한다.
- `client.cpp`: 16종 타일 반복 그리기 대신 방 배경을 카메라 좌표로 그린다.
  플레이어는 기존보다 2배 확대하고 발 위치를 좌표에 맞춰 가구와 비례를 조정한다.
  서버 이동 판정/주변 플레이어 동기화/기존 HUD는 유지한다.

제공 원본과 크레딧은 `assets/maps/clubhouse-sheet.png`에 보존했다.
출처와 추출 방법은 같은 폴더 README에 기록했다. 다른 첨부 파일은 수정하지 않았다.

## 검증

- 실제 SFML 배경+캐릭터 렌더링 확인 (`build/tests/clubhouse-map.png`).
- BFS로 모든 통과 가능 칸이 시작 지점과 연결되는지 검사.
  처음 발견된 고립 구역을 수정한 뒤 통과했다.
- 벽/범위 밖 차단, 이전 큰 맵 좌표와 가구 안 좌표의 안전 보정 검사.
- 기존 로그인 소켓 모의 테스트, 회귀 테스트 총 11개 통과.
- 서버·클라 Debug/Release x64 빌드 통과. 기존 경고는 남아 있다.
- DB 없는 실제 서버 `--startup-check`: 몬스터 0, 작은 방 초기화 완료 확인.
- 실제 DB 로그인/여러 플레이어 접속은 실행하지 않았다.

## 현재 범위와 다음 단계

문·계단은 아직 포털이 아니다. 위층, Sunny Peak, Sunny Cave는 연결하지 않았다.
Tiled 파일을 읽는 로더도 이번에는 추가하지 않았다. 현재는 고정 방+별도 충돌이므로
다음 단계에서 방 출입구와 외부 필드/지역 ID를 추가할 기반으로 사용한다.
전투/채집은 실내에서 발생하지 않는다. 이 작업은 로그인 장애 #19의 해결 검증과는 별개다.

서버와 클라이언트를 모두 새 빌드로 실행해야 한다. 옛 서버와 새 클라를 섞으면
클라 배경과 실제 서버 충돌이 일치하지 않는다. `[READY]` 이후 접속한다.
