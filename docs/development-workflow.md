# 브랜치와 이슈 작업 흐름

통합 이슈: https://github.com/s0o0o/26_Re_GMSEV/issues/12

이번 통합에서는 서버/클라이언트 리팩토링, 닉네임 입력, DB 모듈과 오류 처리,
부하테스트 오류 수정 및 접속 시도 상한까지 누적 커밋을 main에 병합한다.

이전 단계 브랜치들은 서로 이어진 커밋 이력이라 가장 최신 브랜치를 병합하면
모든 이전 단계 커밋도 함께 포함된다. 브랜치를 지워도 main에서 커밋을 찾을 수 있다.

앞으로는 아래 순서로 작업한다.

1. main과 원격 상태를 확인하고 작업 이슈를 발행한다.
2. main에서 `feature/설명` 브랜치를 만든다.
3. 수정·검증하고 `feat : 한국어 설명`으로 커밋한다.
4. main에 병합하고 원격 main을 반영한다.
5. main에 포함된 작업 브랜치를 삭제하고 이슈에 결과를 기록한다.
6. 다음 작업은 다시 main에서 시작한다.

부하테스트의 당시 종료 원인은 실제 재현으로 확정되지 않았다. 이슈 #10은
확인한 코드 결함을 수정한 결과를 기록하며, 장시간 동접 안정성을 보증하지 않는다.
DB 대상 실제 부하 실행 없이 통합 빌드와 자동 회귀 테스트를 검증한다.

서버·클라이언트·스트레스 도구의 x64 Release 빌드와 6개 회귀 프로그램을
확인한다. 회귀 검사는 x64 Native Tools Command Prompt에서
`tests\run-regressions.cmd`로 실행하며 결과물은 무시되는 build/tests에 둔다.
