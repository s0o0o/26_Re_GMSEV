# 35단계: 주민의 산책과 대기 애니메이션

이슈 [#37](https://github.com/s0o0o/26_Re_GMSEV/issues/37), [사전 명세·실행 결과](specs/town-resident-behaviour.md).

## 기존과 지금

이전 주민은 서버에 등록되지만 좌표와 한 장의 포즈가 고정돼 있었다. 이제 Boss/Pashmina는 잠깐 걷고 쉬고, Snoozer는 제자리에서 수면 프레임을 반복한다. 앞으로 캐릭터를 넣을 때 성격에 맞는 idle 또는 자율 행동도 함께 구현하도록 AGENTS.md에 기록했다.

## 코드 흐름

서버의 `OP_WORLD_TICK → serviceRespawns → serviceTownResidents → town_behaviour::tick`이 위치를 결정한다. 클라이언트만 위치를 바꾸는 장식이 아니며 전투용 Lua/몬스터 AI와 계속 분리한다.

- `shared/town_behaviour.hpp`: 주민별 난수/다음 시각, 2~4초 간격의 한 칸 산책 또는 휴식. 집 주변 두 칸과 실내 통행 가능 칸만 사용하며 포털/시작 칸은 제외한다.
- `MonsterState::residentBehaviour`: 몬스터 active/chase와 다른 전용 상태다. 비전투 주민에게 몬스터 AI를 켜서 이동시키지 않는다.
- `serviceTownResidents`: 관찰자가 없으면 쉬고 다음 시각을 갱신한다. 다른 캐릭터의 점유와 대각선 포함 인접 한 칸을 피한다. 좌표/섹터를 갱신하고 기존 시야에는 MOVE, 나간 시야에는 LEAVE, 새 시야에는 ENTER를 보낸다. 밀린 이동을 몰아 처리하지 않는다.
- `town_motion.hpp`: 서버 좌표 사이를 약 350ms 보간한다. 새 패킷이 빨리 와도 현재 표시 위치에서 이어가고 먼 위치/재등장은 즉시 배치한다.
- `town_npc_renderer.hpp`: 원본의 정면 2포즈/방향 포즈/수면 2프레임을 시간으로 고른다. 오른쪽은 측면 포즈를 반전한다. 이름표는 보간된 위치를 따라 중앙 정렬한다. 옆/뒤는 단일 포즈라 완전한 4방향 발동작 사이클이라고 보지는 않는다.

새 스레드나 패킷/DB 필드는 추가하지 않았다. 현재 3명 규모의 처리이며 대규모 주민은 점유 검색/지역 인덱스 최적화가 필요하다. 플레이어가 주민에게 직접 걸어오는 기존 통과 규칙은 유지했다.

## 시각 조정과 검증

초기 Pashmina 정면 idle이 측면으로 바뀌는 것을 발견해 정면 포즈로 바꿨다. 시트의 배경 마스크/기준점은 유지했다. 주민 간 여유 공간을 추가했고, UI 스킬의 연속성과 기존 픽셀 스타일 유지 지침을 참고했다.

정책 검사는 주민별 1시간 분량의 **모의 시간**이다. 4-worker TCP fixture는 같은 생산 행동 함수에 시간을 주입하고 실제 MOVE/LEAVE/ENTER/공격 피드백을 받았다. 일반 게임 서버의 무한 타이머 스레드를 한 시간 실행한 검사는 아니다. 실제 client.cpp 패킷과 OBJECT.draw를 실행했고 보간 중간값/중단/순간이동은 별도 수학 검사로 확인했다.

전체 회귀 30개, 추가 GPU/클라 2개, 주민 TCP 추가 10회, 서버/클라/스트레스 Debug/Release와 DB 없는 startup-check 통과. 초기 C++14 std::clamp 빌드 실패는 min/max로 보완 후 재빌드했다. 실제 DB/부하/일반 게임 플레이/OS 모션 설정은 미검증이며 기존 경고도 남아 있다.
