# 기존300계정 유지 시간 확장

2026-11-15 기준fd9b0fb, #48 / 부모#41. 상태: 검증 완료(이번 기존계정120초 범위).

목적: 이전15초 혼합 부하를 넘어 기존 승인 계정으로120초 유지 조건을 확인한다. 2분은 장시간 soak/최대 수용량 보증이 아니다.

범위: 콘솔 실행기 유지 한도2~300초, 자동 실행 HoldSeconds(기본15), 외부 종료 제한은45초 로그인+유지+여유15초. 도표는 실제 설정 시간을 읽는다. 실제 DB900001000~900001299 기존300행이 모두 있는지 확인 후 trace ON/OFF 각1회 순차 실행. 기존900000000~900000299 보존 개수도 전후 확인. 로그인/이동/종료로 기존 테스트 캐릭터 저장 발생. 신규계정/삭제/스키마·지역·전투·생산서버 변경 없음.

- AC-01: 2/30/120/300초 허용, 1/301/음수/overflow 거부 단위 검사와 모의 TCP 기존 회귀 통과.
- AC-02: 자동 실행의 기본15초 유지, 잘못된 HoldSeconds는 DB 호출/프로세스 시작 전 거부. 선택한 유지 시간+로그인+종료를 외부 제한이 수용한다. 실제 결과 도표에15초를 하드코딩하지 않는다.
- AC-03: 서버Release/실행기 최신 빌드 후, 회귀와 분리하여300명 혼합120초/로그인45초/drain5초를 trace ON/OFF 각1회. attempts/accepted/peak/active/moved=300, 유지완료, 거절/전송/프로토콜/timeout=0, EOF300, 서버오류/저장결과를 기록한다. 실패는 그대로 남기며 P1복귀 여부 판단.
- AC-04: 날짜별 JSON·실측 도표·이슈/작업큐를 갱신한다. #19완료/#41잔여/#10미검증과 기능 로드맵을 구분한다. #48은 이번 범위 완료 때만 닫고 #41은 신규 생성/다른맵·전투/장시간 조건이 남아 열어 둔다.

신규 생성 조건은 승인된 두 범위가 이미 차 있어 추가 범위 승인 없이는 실행하지 않는다. 이번 검사는 클라 본인 이동응답을 최소1회 이상 확인하는 기존 판정이며 모든 명령 응답 지연 상한을 보장하지 않는다. 작업 소유 프로세스만 정리하며 전체 서버 graceful drain 검증은 제외한다.
