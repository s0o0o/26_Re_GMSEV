# 주민 산책과 대기 동작

- 이슈 [#37](https://github.com/s0o0o/26_Re_GMSEV/issues/37), 기준 9e098cf, 2026-11-11. 사전 명세.
- 사용자 요청: 앞으로 캐릭터 추가 시 적절한 idle/자율 행동도 함께 구현.
- 기존: 3명 모두 고정 좌표/단일 정지 프레임. 주민은 전투/Lua 몬스터 AI에서 제외.

## 설계/범위

Boss/Pashmina는 서버 world tick의 별도 주민 행동 정책으로 집 주변 두 칸 범위에서 2~4초 간격의 한 칸 산책/휴식을 한다. Snoozer는 자리를 지키고 원본 수면 프레임을 반복한다. 벽/가구/포털/시작 위치/다른 주민·플레이어 점유 칸은 산책 목적지로 사용하지 않는다. 관찰자가 없는 주민은 이동을 쉬며 복귀 때 밀린 이동을 몰아서 실행하지 않는다.

서버가 위치를 확정하고 기존 ENTER/MOVE/LEAVE로 지역/시야를 갱신한다. 주민 행동은 Lua/몬스터 random/chase와 분리하며 비전투 정책 유지. 클라는 이동 패킷 좌표 사이를 약 350ms 보간하고 방향과 시간에 맞춘 원본 프레임을 선택한다. 재등장 시 순간이동/먼 거리 갱신은 즉시 배치한다. 시간 기반이며 렌더 횟수에 영향을 받지 않는다.

모션의 목적은 주민이 살아 있는 느낌과 이동 연속성이다. 픽셀 외형/이름표 중앙 정렬 유지, 스프라이트 source rectangle만 사용하고 새 그림/원본 파일 편집 없음. 범위는 소규모 주민 3명이며 대화/일정표/퀘스트/경로탐색/새 주민/지역2B/DB 변경은 제외한다.

## 완료 기준

| ID | 기준 | 검증 |
| --- | --- | --- |
| AC-01 | 장기 모의 tick에서 유효 칸/홈 반경/포털·점유 금지, 같은 시간 중복 실행 금지, Snoozer 고정 | 순수 정책/시간 주입 단위 |
| AC-02 | 실제 world tick에서 주민 이동 후 관찰자 MOVE/LEAVE/ENTER 및 시야 상태 일치, 무관찰자 휴식 | 실제 4-worker TCP DB 대역, tick 시간 주입 |
| AC-03 | source frame 변화와 방향 선택, 연속 이동 보간·중단·재등장 안전 | 실제 클라 packet fixture + 순수 보간 + SFML 출력 |
| AC-04 | 주민 비전투와 기존 몬스터/지역 회귀 유지, 서버/클라/스트레스 빌드 통과 | 전체 회귀/Debug·Release/DB 없는 startup-check |
| AC-05 | 사용자 미리보기와 추가 캐릭터 행동 규칙 기록 | 생산 렌더 기반 여러 시간대 이미지/육안 확인 |

성능은 주민 수에 비례한 소규모 tick이며 전체 NPC에 새 스레드를 만들지 않는다. 실제 DB/부하/모든 모니터/일반 게임 플레이 육안은 실행 여부를 구분한다. 긴 시간 검사는 모의 시간이며 실시간 대기와 구분한다.
