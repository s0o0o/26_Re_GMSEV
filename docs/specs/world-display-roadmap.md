# 월드 확장과 화면 대응 로드맵

- 기준: de22890, 2026-11-11. 이슈 [#34](https://github.com/s0o0o/26_Re_GMSEV/issues/34). 상태: 1단계 구현·검증 완료, 2~6단계 예정.
- 사용자 목표: 넓은 필드 유지, 하나의 마을/집 거점, 귀환 버튼, 첨부 픽셀 리소스 기반 커마 확장, 가변 창과 전체화면.
- 초기 가정: 공용 클럽하우스와 마을 로그인. 개인 집/마지막 위치 복원은 아직 확정하지 않는다.

## 순서와 단계 경계

1. 화면 대응: 기존 900×800 논리 좌표/시야 유지, 창 맞춤/최대화/리사이즈, F11 테두리 없는 전체화면, Escape로 창 복귀. 비율 차이는 여백으로 처리. UI 재배치와 넓은 시야는 후속 단계.
2. 지역 ID: 먼저 [2A 지역 경계·기존 좌표 호환](world-region-boundaries.md), 다음 2B 독립 지역 좌표/지역별 섹터/패킷·DB 위치 마이그레이션으로 분할. 2A는 기존 패킷/저장 형식을 유지하고 2B는 클라/서버/스트레스 버전 동시 변경.
3. 거점↔필드 전환과 귀환: 서버가 목적지 결정, 중복 요청 거부, 이전 지역 정리, 새 지역 목록/카메라 초기화. 실패/접속 종료 경계 검사.
4. 넓은 필드: 청크 단위 배경/충돌 데이터, 초원·강·절벽 등 연결 지형. 기존 큰 필드를 단순 상수 복원으로 취급하지 않는다. NPC 활성 범위와 부하 예산 결정 후 크기 확정.
5. 클럽하우스 옷장/커마: 블러/중앙 정렬 유지, 카테고리 아이콘과 아이템 미리보기, 방향별 착용 정렬, 저장/재접속/다른 플레이어 외형 동기화.
6. 동굴 등 추가 지역과 실제 DB 동접 검증. 실제 부하는 별도 데이터 변경 안내 후 진행.

각 단계는 별도 이슈/사전 명세/feature 브랜치로 완료 및 main 병합한다. 이 문서 작성이 모든 단계 구현 완료를 뜻하지 않는다.

## 이번 1단계 범위와 완료 기준

- AC-01: 900×800, 1280×720, 1920×1080, 2560×1440, 3440×1440, 세로 창에서 내용이 잘리지 않고 종횡비가 유지된다. 0 크기는 계산/입력에서 안전하게 거부한다.
- AC-02: 같은 논리 버튼 중심은 크기 변경 뒤에도 같은 버튼으로 클릭된다. 여백 클릭은 전달하지 않는다.
- AC-03: F11 전환/복귀 때 창 크기와 위치를 복원한다. Escape는 전체화면에서 창 복귀를 먼저 처리한다. 로그인/커마/접속/게임 단계에 공통 적용하며 재접속하지 않는다.
- AC-04: 클라이언트 Debug/Release 빌드, 좌표 단위 검사, SFML 렌더/입력 fixture 및 기존 커마 preview 회귀를 실행한다. 실사용 모니터/배율 검증은 실행 여부를 구분한다.

이번에는 서버·DB·프로토콜·시야 범위를 바꾸지 않는다. 작은 창에서 글자 가독성을 무제한 보장하거나 울트라와이드 추가 시야를 제공하지 않는다. 고해상도 DPI/다중 모니터와 기기별 표시 품질은 별도 실제 확인이 필요하다.

## 1단계 결과 (2026-11-11)

- AC-01: `display_layout.hpp` + `display_layout_test.cpp`. 명시한 크기 외 320×240/1×1/0 크기 검사 통과. SFML 렌더 fixture는 900×800/1280×720/1920×1080/600×1000/3440×1440 이미지를 생성했다. 1920×1080/600×1000 출력 육안 확인. 물리 모니터를 이 해상도로 바꾼 검사는 아니다.
- AC-02: `WindowDisplay::resize/acceptsClick`가 viewport를 맞추고 여백 클릭을 중앙 이벤트 처리에서 거부. 실제 SFML mapPixelToCoords와 커마 비쥬 선택 이벤트 검사 통과. 좌표 단위 검사는 여백/외부 좌표 거부 확인. 렌더 fixture는 커마 본체이며 접속/돌아가기 버튼을 포함한 전체 로그인 동선의 육안 검사는 아니다.
- AC-03: 실제 SFML 창 생성/재생성에서 F11 반복 억제, 전체화면 왕복, 크기·위치 복원, Escape 창 복귀, 재생성 뒤 외형 텍스처 렌더 검사 통과. 생산 client.cpp의 공통 이벤트 루프에 연결했음을 코드 확인. 네트워크 코드와 세션 객체는 변경하지 않았다. 실제 DB 접속 중 왕복은 미실행.
- AC-04: 클라이언트 x64 Debug/Release 성공. `tests/run-display.cmd` 2개 통과, 기존 `tests/run-customizer-preview.cmd` 통과, `tests/run-regressions.cmd` 24개 통과. 기존 C4244/MSB8028/LNK4098 경고 잔존. 최소화 시 0 크기의 나눗셈 방지는 단위 검사, 실제 OS 최소화/다중 모니터/고DPI는 미검증.
- 초기 검사에서 float 반올림으로 음수 극소 여백이 생긴 실패를 보정했다. include 순서로 CRT 경고 매크로 적용이 늦어진 초기 빌드 실패도 수정했다. 채팅 문자열 복사는 같은 제한 길이의 strncpy_s로 바꿨다.
- UI 스킬의 검출 도구는 C++ 파일 경로에서 ENOENT로 실패해 통과로 간주하지 않았다. C++ 빌드·좌표 검사·SFML 실행·출력 이미지로 별도 검증했다.

조작/설명은 [32단계 기록](../refactoring-step-32.md). 후속 단계의 AC와 이슈는 각 단계 시작 시 구체화한다.
