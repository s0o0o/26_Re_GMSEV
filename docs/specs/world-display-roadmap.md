# 월드 확장과 화면 대응 로드맵

- 기준: de22890, 2026-11-11. 이슈 #34. 상태: 1단계 구현 전.
- 사용자 목표: 넓은 필드 유지, 하나의 마을/집 거점, 귀환 버튼, 첨부 픽셀 리소스 기반 커마 확장, 가변 창과 전체화면.
- 초기 가정: 공용 클럽하우스와 마을 로그인. 개인 집/마지막 위치 복원은 아직 확정하지 않는다.

## 순서와 단계 경계

1. 화면 대응: 기존 900×800 논리 좌표/시야 유지, 창 맞춤/최대화/리사이즈, F11 테두리 없는 전체화면, Escape로 창 복귀. 비율 차이는 여백으로 처리. UI 재배치와 넓은 시야는 후속 단계.
2. 지역 ID: 공용 거점/필드/실내 구분, 지역별 섹터·시야·공격·AI generation 검증, 패킷과 DB 위치 마이그레이션. 클라/서버/스트레스 버전 동시 변경.
3. 거점↔필드 전환과 귀환: 서버가 목적지 결정, 중복 요청 거부, 이전 지역 정리, 새 지역 목록/카메라 초기화. 실패/접속 종료 경계 검사.
4. 넓은 필드: 청크 단위 배경/충돌 데이터, 초원·강·절벽 등 연결 지형. 기존 큰 필드를 단순 상수 복원으로 취급하지 않는다. NPC 활성 범위와 부하 예산 결정 후 크기 확정.
5. 클럽하우스 옷장/커마: 블러/중앙 정렬 유지, 카테고리 아이콘과 아이템 미리보기, 방향별 착용 정렬, 저장/재접속/다른 플레이어 외형 동기화.
6. 동굴 등 추가 지역과 실제 DB 동접 검증. 실제 부하는 별도 데이터 변경 안내 후 진행.

각 단계는 별도 이슈/사전 명세/feature 브랜치로 완료 및 main 병합한다. 이 문서 작성이 모든 단계 구현 완료를 뜻하지 않는다.

## 이번 1단계 범위와 완료 기준

- AC-01: 900×800, 1280×720, 1920×1080, 2560×1440, 3440×1440, 세로 창에서 내용이 잘리지 않고 종횡비가 유지된다. 0 크기는 계산/입력에서 안전하게 거부한다.
- AC-02: 같은 논리 버튼 중심은 크기 변경 뒤에도 같은 버튼으로 클릭된다. 여백 클릭은 전달하지 않는다.
- AC-03: F11 전환/복귀 때 창 크기와 위치를 복원한다. Escape는 전체화면에서 창 복귀를 먼저 처리한다. 로그인/커마/접속/게임 단계에 공통 적용하며 재접속하지 않는다.
- AC-04: 클라이언트 Debug/Release 빌드, 좌표 단위 검사, SFML 렌더/입력 fixture 및 기존 커마 preview 회귀를 실행한다. 실사용 모니터/배율 검증은 실행 여부를 구분한다.

이번에는 서버·DB·프로토콜·시야 범위를 바꾸지 않는다. 작은 창에서 글자 가독성을 무제한 보장하거나 울트라와이드 추가 시야를 제공하지 않는다. 고해상도 DPI/다중 모니터와 기기별 표시 품질은 별도 실제 확인이 필요하다.
