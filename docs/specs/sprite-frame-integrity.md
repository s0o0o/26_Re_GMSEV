- AC-02 플레이어2종/90외형·방향 및 사용 중 몬스터 프레임을 검사한다. 변경 없는 검사도 수정했다고 부풀리지 않는다.

- AC-04 관련 회귀·클라Debug/Release·실제 렌더러 미리보기/다중크기를 실행하고 원본 해시·idle/행동 보존을 확인한다. 실제 OS 캡처와 렌더러 출력을 구분한다.
- AC-05 구조·AI 활용 기록/이슈/검증·main 원격 포함·안전 브랜치 정리 후 완료한다.

접근: 고정 crop을 무조건 키우지 않고 원본의 프레임 셀과 내용 경계를 비교한다. 인접 프레임이나 크레딧이 섞이면 실패다. 현재 화면이 원본부터 잘린 경우와 코드 crop 잘림을 구분한다. CP949 client.cpp는 roundtrip 확인 후 최소 변경한다.

## 조사·수정 결과

원본 셀을 기준으로 Boss 정면phase0/1에서22/32픽셀, Pashmina 정면phase1에서40픽셀·뒤방향에서5픽셀, Snoozer 수면phase1에서55픽셀이 기존 crop 밖에 있었다. 초기 ±3px 탐색은 인접 프레임도 세는 경우가 있어 최종 검사는 명시한 원본 셀의 전체 내용과 비교한다. 변경 후 주민3종×방향4×phase2=24경우에서 누락0·혼입0을 assert한다. 원본 PNG/2배 배율/발기준 tileY+46·대기/산책 정책은 유지했다.

플레이어 원본8프레임 픽셀 일치와90외형 alpha/nearest 회귀는 변경 없이 통과했다. monHam은208×52/52셀로 검사·육안 확인했고 crop 수정 없음. 훈스터 작은 버전은50×50인데52×52 source rect를 요청하므로 전체 source 크기에서 rect를 만들도록 수정했다. 이 경우는 원본 픽셀 누락이 아니라 텍스처 밖 참조 정리이며 실제 ENTER 대역에서50×50을 검사한다.

HUD 겹침 라벨은 기존 기록의 SPEED가 아니라 실제 SEED다. nameSlot(242,678,128,31)에 glyph bounds를 맞춰 이름이 라벨로 넘지 않게 한다. 짧은/기존 테스트명/허용 최대12자 영문·한글의 bounds를 생산 글꼴로 검사한다. 서버의 전체 이름이나 저장값을 자르지 않는다.

미리보기 `sprite-frame-before-after.png`는 기존/수정 crop을 같은 원본에서 그린 진단 렌더, `profile-name-*.png`는 실제 프로필 raster/글꼴/배치 함수의 렌더러 검사다. 실제 게임 OS 캡처가 아니다. 원본 자체의 스타일/제작 당시 잘림 여부나 미사용21종 모든 포즈의 정상성을 보증하지 않는다.
