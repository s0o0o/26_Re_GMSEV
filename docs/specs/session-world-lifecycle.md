## 목적

퇴장한 플레이어의 시야·섹터·추격 흔적을 정리하고, 다중 세션에서 같은 전투·재생성 결과를 받게 한다. 과거 채팅 없이도 구현 의도와 테스트 보장의 경계를 알 수 있게 한다.

## 범위와 제외 범위

포함: 기존 종료 정리, AI 세대/접속 번호 검사, 전투 알림 필터, 씨앗·몬스터 재생성의 동작 계약과 증거. 이번 #28에서는 문서·작업 절차만 추가한다.

제외: 게임 기능 변경, 외부 도구 설치, DB 스키마 변경, 새 패킷, 전체 IOCP 수명 개선 구현, 실제 DB 부하 실행, 게임 창 다중 실행, 타이머 정밀도 보장.

가정: 현재 고정 필드 배치와 서버 내부 ID 범위를 사용한다. registry 동시 접근 및 종료 직후 비동기 완료의 객체 수명 안전성은 별도 검토 대상이다.

## 현재 동작과 목표 동작

이전에는 소켓 종료 뒤 섹터·자기 시야가 남고, 본인 시야에 없는 상대의 퇴장 알림을 놓칠 수 있었다. 숫자 ID만으로는 재접속을 구별하기 어려웠다.

현재 코드는 아래 목표를 이미 구현한다. 이번 문서화는 새 동작을 약속하는 작업이 아니다.

1. `disconnect()`가 종료 플래그를 중복 방지용으로 설정하고 `detachWorldPresence()`를 호출한다. 모든 섹터에서 ID를 지우는 콜백, 자기/다른 세션 시야 정리, 관찰자 퇴장 알림을 수행한다. 소켓 종료와 기존 DB 저장은 `disconnect()`에 남는다.
2. 해당 플레이어를 추격하는 몬스터만 세대 증가·추격 중단·비활성화한다. `connectionId`는 같은 ID의 다른 접속 객체를 구분한다. 예약된 `OP_PLAYER_MOVE`는 실행 전 접속 번호와 연결 상태를 검사한다.
3. `publishCombat()`과 부활 알림은 `forWorldPlayers()`로 정상 게임 세션만 선택한다. 사망 시 전투 결과 다음 사망 알림을 보내고 시야에서 제거한다.
4. 씨앗은 획득 20초 뒤 복구 가능, 몬스터는 사망 30초 뒤 원래 위치·HP 5로 복구 가능하다. 서버는 약 1초마다 확인하므로 실제 표시는 늦을 수 있다. 사망·부활 전 AI 세대는 거부한다.

## 영향

- 서버: [이벤트·종료 정리](../../TP_2023192003/TP_2023192003/world_events.hpp), [접속 객체](../../TP_2023192003/TP_2023192003/game_session.hpp), [수명 정책](../../TP_2023192003/TP_2023192003/monster_lifecycle.hpp), [서버 호출부](../../TP_2023192003/TP_2023192003/myserver.cpp), [맵 복구](../../TP_2023192003/TP_2023192003/world_map.cpp).
- 클라이언트: 기존 전투·사망·입장·맵·퇴장 패킷을 받는다. 이번 도입에서는 UI/클라이언트를 변경하지 않는다. 실제 화면 동작은 아래 테스트로 보장하지 않는다.
- 프로토콜: [공유 프로토콜](../../shared/protocol.hpp)의 기존 패킷 사용. AI generation/connectionId는 서버 내부 값이며 패킷·DB 필드가 아니다.
- DB/운영: 기존 종료 저장 경로 유지. 이번 테스트는 DB에 연결하지 않으며 계정을 만들지 않는다.

## 오류·경계 상황

종료 중/전송 실패/로그인 중/없는 세션은 이벤트 수신자에서 제외한다. 비대칭 시야와 중복 정리를 처리한다. 다른 대상을 추격하는 몬스터는 유지한다. 같은 숫자 ID라도 접속 번호가 다르면 이전 알림은 거부한다. 부활 시각 직전에는 복구하지 않고 정각부터 복구 가능하며 반복 호출로 중복 복구하지 않는다. 씨앗 위에 서 있기만 해서는 다시 자동 획득되지 않는다.

이 검사는 늦은 네트워크 RECV/SEND 완료가 해제된 메모리나 새 접속에 적용되는 문제 전체를 해결한 증거가 아니다.

- 과거 기록: [25단계](../refactoring-step-25.md)는 회귀 15개, TCP 테스트 단독 10회, 서버 Debug/Release, DB 없는 startup-check 통과를 보고한다. **이번 문서 도입에서 재실행한 결과와 혼동하지 않는다.**
