# DB 위치 계약 검증과 지역 위치 저장 경계

- 이슈 [#39](https://github.com/s0o0o/26_Re_GMSEV/issues/39), 사전 기준 eb5a4de, 2026-11-13. 상태: 구현 전.
- 현재 DB 조회는 get_user_info의 9개 결과 순서에 의존한다. 열 개수/이름/형식과 요청 계정 일치 검사가 부족하다. X,Y→지역 내부 위치 변환은 저장 경계가 아닌 로그인 코드에 흩어져 있다.

## 범위

1. 프로젝트 DSN으로 접속하되 계정 행이나 사용자 프로시저를 실행하지 않는 메타데이터 진단 도구. 읽기 전용 연결 요청, 로그인/쿼리 timeout, sys.columns/parameters/결과집합 설명만 SELECT. DSN/계정/암호/연결문자열은 출력하지 않는다. 실제 연결 성공/실패를 구분한다.
2. 9열 로그인 계약의 열 수·열 이름·정수 타입·NULL/잘림·요청 ID 일치 및 다중 행 거부. 검증 전 출력 매개변수를 변경하지 않는다. 실패는 Error이지 NotFound가 아니므로 계정을 생성하지 않는다.
3. 지역+지역 내부 좌표의 저장/복원 경계 codec. 기존 DB X,Y에 대한 엄격 encode와 기존 잘못된 위치의 거점 복구를 구분한다. 실제 저장 호출에서 codec를 사용하고 임의의 잘못된 지역 위치 저장은 막는다.

실제 DB 계정 생성/행 조회·저장/DDL/프로시저 변경/패킷 버전 변경은 이번 진단에서 하지 않는다. 실제 DB 계약을 얻기 전 이를 추정해 마이그레이션하지 않는다. 기존 게임 상태/프로토콜은 계속 기존 좌표이며 지역 위치를 전부 직접 저장하게 됐다고 보고하지 않는다.

## 완료 기준

| ID | 기준 | 검증 |
| --- | --- | --- |
| AC-01 | 진단 SQL은 메타데이터만 읽고 비밀/계정 값 미출력, 실제 성공/실패 기록 | 소스 확인·빌드·실제 읽기 전용 시도 |
| AC-02 | 열 변경/형식/NULL·잘림/다른 계정/다중 행을 Error로 처리하고 출력 미변경, NotFound와 구분 | 생산 validator/단위 및 DB 대역 로그인 경계 |
| AC-03 | 지역 위치↔기존 DB 좌표 왕복·invalid 저장 거부·기존 invalid 복원 정책 구분 | codec 전체 칸/범위 단위 및 실제 저장 어댑터 대역 |
| AC-04 | 서버/클라/스트레스 빌드, 전체 회귀, 초기화 성공 | 실제 실행/미실행 구분 |
| AC-05 | 사용자 설명과 미리보기 | 생산 codec/기존 맵 렌더 기반 진단 PNG |

기존 DB mutex/world 잠금 경계를 유지하고 DB I/O는 world 밖에서 수행한다. CP949 소스 보존. 실제 ODBC 로그인 조회를 테스트하지 않았다면 DB 대역/validator 검사를 실제 조회 성공으로 확대하지 않는다.
