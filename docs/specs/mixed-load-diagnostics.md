# 혼합 부하·종료 송신 오류 계측

2026-11-13, 기준426e5f0, [#41](https://github.com/s0o0o/26_Re_GMSEV/issues/41). 상태: 계측/종료 개선 검증 완료(#43), 병목 전체는 미완료·부모 OPEN.

최근 혼합 부하는 291명에서 timeout, 분리 부하는300명/15초 유지 성공했으나10053 송신 실패300행이 남았다. 같은 워크로드를 관측하고, 로그인 중 이동과 종료 수신 drain을 각각 선택하여 구분한다. 프로토콜/DB 스키마 변경·world 잠금 제거·시간 제한 증가는 범위 밖이다.

## 완료 기준

- AC-01: opt-in trace는 단일 파일에 ms/connectionId/이벤트/시간 값을 기록한다. 계정/닉네임/DSN을 기록하지 않는다. 로그인 DB/commit-world 대기/완료 큐/완료 세션잠금·world대기·입장완료, 송신 실패, disconnect·저장 완료를 연결한다. world/DB 잠금 측정이 동기화 의미를 바꾸지 않는다.
- AC-02: 콘솔에 mixed/separate와 immediate/drain 종료 선택을 추가한다. 300명/45초 로그인/15초 hold는 그대로 유지한다. 단계 시각과 종료 drain의 EOF/timeout/버려진 수신량을 별도 기록한다. drain 중 gameplay 성공 통계를 바꾸지 않는다.
- AC-03: DB 없는 mock TCP에서 혼합/분리·조각 패킷과 drain 종료/timeout을 검증, 전체 회귀 및 서버Debug/Release·기존stress 빌드.
- AC-04: 이전 승인 전용300계정(900000000~900000299)을 중복 검사 후 재사용한다. 실제 DB 생성/저장 발생을 명시하고 수정 전/후 또는 시나리오별 결과·trace를 보존한다. 실제 실패는 실패로 남기며 원인과 관측 상관관계를 구분한다.
- AC-05: 확인된 원인에 한해 수정/회귀를 추가하고 사용자 설명·실측 미리보기·다음 작업을 기록한다. 일부 기준 미완료면 #41 전체를 해결로 닫지 않는다.

생산 서버 graceful shutdown 구현/장시간 soak/그래픽 클라 검증은 제외한다. 테스트 소켓 drain과 서버 전체 저장/IOCP drain 완료는 다른 기준이다. owned 프로세스만 종료하고 테스트 계정은 삭제하지 않는다. 기존 C++ CP949를 보존한다.

범위 추가: 재사용 계정의 혼합 부하에서 원래 timeout이 재현되지 않아, 사용자가 신규 전용 ID900001000~900001299의300개 추가 생성을 승인했다. 기존300개는 보존하고 새 범위 COUNT=0/중복 없음 확인 뒤 혼합 부하로 검사한다. 선택 가능한 실행 범위는 이 두 승인 범위로 제한한다.

## AC별 결과 (2026-11-13)

- AC-01 실행 통과: `shared/load_trace.hpp`와 생산 로그인/송신/disconnect/잠금 경계 연결. 별도 파일·시각·connectionId 연결, 동시800줄 및 재귀 잠금 검사 통과. world 기록은20ms 이상만, 개별 로그인 대기 이벤트는 전체 기록. DB 측정은 조회/생성 호출 전체 시간이며 개별 SQL/DB mutex를 따로 분리한 값은 아니다. 시작 시 경로가 없으면 trace 출력 없음.
- AC-02 실행 통과: 콘솔 모드/5초 수신 drain, hold 기준과 종료 기준 분리. EOF를 거절한 모의 peer는 hold 성공 뒤에도 최종 실패한다. 포트 localhost/계정·접속·시간 상한 유지. cleanup 숫자가 기존 게임 성공 카운터를 바꾸지 않는지 확인.
- AC-03 실행 통과: 전체36개 회귀, 서버Debug/Release와 기존stress Debug/Release 빌드, startup-check. 신규 trace 단위 및 기존 콘솔 fixture 확장. 클라이언트 소스/빌드는 이번에 변경·실행하지 않았다. 기존 C4244/LNK4098 경고 잔존.
- AC-04 실제 실행: 기존 계정 세 시나리오와 새 승인 계정 혼합 한 시나리오, 총4회. 생성 전COUNT0, 실행별 해당 범위 최종300/중복 없음. 기존 범위300 보존 확인. 상세 [JSON](../test-results/mixed-load-2026-11-13.json)·[설명](../refactoring-step-39.md). 신규 혼합은 최종 **실패**(drain timeout300), 나머지 결과와 합쳐 통과로 바꾸지 않는다.
- AC-05 부분 완료: 즉시close후10053 관측에 대응하는 콘솔 수신 drain 추가, 실제 기존계정 비교에서300→0건. 새계정 혼합은 여전히 종료 지연이며 같은 방식이 무조건 해결하지 않는다. 계측 단계 #43만 완료하고 부모 #41은 대기열·처리량/원래 timeout 재현을 위해 OPEN 유지한다. 네 실행 비교 PNG 생성/육안 확인(실측 도표, 게임 화면 아님).

기존계정 혼합: DB최대16ms/완료 큐469ms/수신→ready554ms. 신규계정 혼합: DB최대16ms/완료 큐1202ms/수신→ready1274ms/전원로그인37.481초. 각 차이는 관측값이며 인과 확정이나 trace 없이 같은 성능 보장이 아니다. 모든 실행의 송신 오류는 클라이언트 shutdown 시작 이후였다. 이는 과거 사용자10053의 최초 원인을 설명하지 않는다. 저장성공반환은4회 각300건, 전체 서버 drain/DB readback은 미검증이다.

첫 분석 명령은 잘못된 작업 디렉터리로 실패했으며 루트에서 재실행 성공했다. 데이터 변경 없이 원인 확인용 명령만 재실행한 것이다. 원본 로그 보존, 계정 총600개 미삭제. 다음은 부모 #41의 남은 처리량/완료 큐 지연 범위다.
