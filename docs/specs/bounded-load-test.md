# 300명 제한형 부하 검증

이슈 [#40](https://github.com/s0o0o/26_Re_GMSEV/issues/40), 기준 79816ac, 2026-11-13. 상태: 실행기·제한형 검증 완료, 미해결 혼합 부하는 #41로 분리.

사용자는 DB 연결 확인과 기존 스트레스 도구의 300명 실행을 요청했다. 기존 도구는 ID 0부터 사용하며 무한 worker/종료 대기를 사용한다. 이를 보존하고 같은 공유 프로토콜 기반의 제한형 콘솔 실행기를 추가한다. 지역 좌표 전환은 이번 부하 진단 뒤로 순서를 변경한다.

실제 DB 전용 ID 900000000~900000299 생성·저장에 사용자 동의를 받았다. 실행 전 해당 범위 COUNT만 읽고 0이 아니면 중단한다. 테스트 후 계정은 자동 삭제하지 않는다. 실제 DB 로그인/종료 저장이 발생한다. 로컬 서버가 이미 있으면 임의 종료하지 않는다.

## 완료 기준

- AC-01: localhost 전용, 1~300명/명시 ID 범위/시간 제한, 잘못된 설정은 접속 전 거부. 비동기 connect/부분 송수신/분할·합친 패킷/유효성 검사, 로그인 deadline 및 종료.
- AC-02: 시도/로그인 성공/거절/전송·프로토콜 오류/최대 동접/유지 완료 시 동접/본인 이동 응답을 기록한다. 300회 시도를 동접 300으로 보고하지 않는다. 목표 전원 접속 및 지정 유지 시간/이동 응답 없으면 실패 종료한다.
- AC-03: DB 없는 TCP fixture로 성공/거절/끊김/timeout/잘못된 패킷과 부분 송수신을 검증하고 생산 서버/기존 stress 빌드를 실행한다.
- AC-04: 실제 DB metadata 연결 성공 여부를 기록한다. 사용자 승인 범위의 기존 행 개수 0 확인 뒤 실제 서버+300명 부하를 실행하고 결과/한계를 구분한다. 서버는 본 작업에서 띄운 프로세스만 종료한다.
- AC-05: 명령/결과/미리보기/다음 작업을 문서 및 이슈에 기록한다. 그래픽 변경은 없으며 미리보기는 테스트 결과 도표임을 표시한다.

장시간 soak/최대 수용량/대규모 전투·필드 AI 성능/DB 스키마 변경/기존 GUI 도구의 전체 동시성 개편은 제외한다. 실제 실패 시 원인을 기록하며 안정성을 보증하거나 기존 #10/#19를 근거 없이 닫지 않는다.

1. `load-20261113-163057-18286ac6`: 실제 혼합 부하 실패. 300시도/291로그인/peak291/본인 이동 응답 290명/timeout1/49.079초. 먼저 접속한 peer가 이동하면서 나머지 로그인도 시도했다. DB 계정 292개 생성 후 실행 종료. 서버 프로세스는 유지됐지만 병목 원인은 확정하지 않는다.
2. 실행기를 로그인 단계와 이동 단계로 나눈 뒤 같은 승인 계정을 재사용했다. `load-20261113-163343-11073c81`: 실제 분리 부하 통과. 300시도/300로그인/peak300/종료 전 active300/본인 이동 응답300명, 전원 로그인 뒤 15초 유지, 총19.733초. 클라이언트가 관측한 거절/전송/프로토콜 오류/timeout 0. 최초 292개를 재사용하고 추가 8개 생성. 실제 DB 최종 행 수300 확인.
3. 두 번째 서버 로그에는 `Send submission failed ... error=10053` 300행이 남았다. 클라이언트 종료가 송신 drain을 보장하지 않으며, 타임스탬프가 없어 정확한 발생 단계를 이 로그만으로 단정하지 않는다. SQLExecute/계약 오류 패턴은 관측되지 않았지만 전체 저장 성공 증거를 대신하지 않는다. 3초 종료 대기 후 서버 생존 확인 뒤 본 작업에서 띄운 서버만 강제 종료했다. graceful shutdown/전체 저장 완료 검증은 미실행이다.

후속 [#41](https://github.com/s0o0o/26_Re_GMSEV/issues/41)은 혼합 부하 지연과 종료 송신 오류의 계측·재현이다. 이번 로그인/이동 단계 분리는 서버 병목 수정이 아니며 #10/#19도 유지한다. 승인 계정 300개는 삭제하지 않았다. 지역 좌표 전환은 부하 진단 이후로 순서 변경했다.

실제 두 실행 뒤 중복된 서버 세션 ID를 성공 동접으로 세지 않도록 guard를 추가했다. 이 guard는 최종 단위 검사와 300명 모의 TCP/오류 경로 재실행으로 통과했으며 실제 DB를 세 번째 실행한 것은 아니다. 원본 실제 로그는 guard 추가 전 결과로 보존한다.

초기 도표 생성에서 Font 생성자 overload 선택 오류가 발생해 명시적 float 생성자로 수정 후 재실행했다. 기존 GUI의 무한 루프/자료 경쟁 전체는 이번 변경으로 고쳤다고 보고하지 않는다.
