# 넓은 필드 청크·충돌 기반 (자율 큐2)

2026-11-16, 기준 main 93250e3, #54. 상태: 구현·실행 검증 완료. main 포함 증거는 #54 최종 댓글에 기록한다. 큐1 귀환은 #53에서 완료했고, 큐3 옷장·커스터마이징은 아직 남아 있다.

## 목적·현재 문제

SunnyPeak descriptor는 20×18이고 배경 한 장·legacy dense map_data에 의존한다. 거점 분리는 되었지만 사용자가 원하는 넓은 탐험 필드가 아니다. 크기 상수만 늘려 배경 밖/충돌 불일치를 만드는 것으로 끝내지 않는다.

## 범위와 방향

- 공용 Clubhouse는 24×18 그대로 하나만 유지한다. 개인 집/DB region 열/새 계정 생성은 제외한다.
- SunnyPeak를 256×256 내부 좌표로 확장한다. int16 wire와 기존 DB legacy X=32+localX, Y=localY 범위를 넘지 않는다. DB 실제 스키마/데이터를 변경하거나 부하 계정을 추가하지 않는다.
- 패킷 배치는 같지만 지역 범위 계약이 넓어지므로 프로토콜 v4로 올린다. 옛 v3 클라가 범위 밖 MOVE를 받은 뒤 실패하는 대신 로그인에서 버전을 거절한다. 모든 도구를 함께 다시 빌드한다.
- 16×16 청크를 기준으로 결정적 지형·충돌을 공유한다. 기존 시작 20×18 아트/포털/귀환 지점은 보존하고 동쪽 연결 통로로 초원·강/다리·절벽 지역을 연결한다. 기존 원본 이미지의 타일을 재사용한다.
- 서버는 전체 월드 dense 배열 대신 제한된 지형 청크 캐시와 수집/리스폰 상태를 분리한다. 캐시가 퇴거되어도 수집한 씨앗이 되살아나지 않는다. 클라는 가시 청크/타일만 그리며 맵 전체 크기의 텍스처를 만들지 않는다.
- 기존 NPC의 idle/자율 행동·관찰자 기반 활성화는 보존한다. 대량 NPC 추가/게임 밸런스 재설계가 아니라 데이터·충돌·표시 기반 작업이다. 먼 경로 요청에는 탐색 예산을 둬 worker가 전체 필드를 무제한 탐색하지 않도록 한다.

## 오류·경계와 구현 전 확인

legacy cameraY(int y)는 지역을 알 수 없으므로 넓은 필드의 canonical 카메라를 대신하지 않는다. 생산 경로는 Position 기반을 유지한다. 시작점/몬스터 원본/씨앗 자료의 기존 legacy 경계는 명시적으로 변환한다. invalid 위치가 캐시 키나 배열 인덱스로 들어가지 않게 한다.

테스트에서 기존 작은 descriptor의 x=20을 invalid라고 적은 검사는 새 실제 끝값으로 옮기되, 과거 시작 구역의 벽/충돌 검사를 지우지 않는다. 원본 이미지의 비타일 구역/크레딧/배경색을 지형으로 잘라 넣지 않는다. 미리보기는 생산 렌더러 출력과 실제 OS/DB 캡처를 구분한다.
